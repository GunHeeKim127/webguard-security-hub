# 공개 주소 진단과 Hub 접속 보호

## 주소 입력

기본 `SCAN_TARGET_POLICY=public`에서는 진단 권한이 있는 로그인 계정(admin/analyst)이 공개 HTTPS 기본 주소를 입력하고 소유·진단 허가 확인란을 체크하면 요청할 수 있습니다. DB나 `ALLOWED_SCAN_HOSTS`에 없는 주소라는 이유만으로 거절하지 않습니다. 체크는 사용자 선언이며 DNS/파일 토큰 등으로 소유권을 증명하는 기능은 아닙니다. 신규 viewer는 기존대로 조회 권한만 갖습니다.

주소가 바뀌면 실행 중인 진단·현재 로그·개선안·권한 체크를 초기화합니다. 같은 주소의 최신 성공 결과 덮어쓰기는 유지합니다. `SCAN_TARGET_POLICY=approved`를 명시하면 예전의 정확한 `ALLOWED_SCAN_HOSTS` 제한으로 돌아갑니다. 알 수 없는 정책 값은 오류로 처리합니다.

사전 등록을 없애도 SSRF 방어는 유지됩니다. 공개 DNS의 모든 IP가 공개 unicast인지 확인하고 한 IP로 연결을 고정합니다. IP 직접 입력, 내부망, HTTP, 다른 포트, 상세 경로·쿼리·fragment, 자격증명 URL을 거절합니다. HTTPS/443 루트에 HEAD 1회만 보내고, TLS 인증서를 검증하며 리디렉션과 본문은 따라가지 않습니다. 잘못된 주소나 실패한 진단을 입력했다는 이유만으로 요청자를 공격자로 차단하지 않습니다.

## 진단 응답과 공격 요청의 구분

진단 대상 서버의 IP와 Hub에 접속한 사용자의 IP는 서로 다릅니다. 진단 응답은 실행하거나 HTML로 삽입하지 않습니다. 헤더 16KiB 제한과 타입·규칙 검사를 적용하고 쿠키 값 등은 저장하지 않습니다. 잘못된 TLS/헤더·시간 초과는 진단 실패로 처리합니다. 단순 보안 헤더 누락이나 비정상 응답만으로 대상 서버/CDN IP를 공격자로 단정해 블랙리스트에 넣지 않습니다.

자동 IP 차단은 **우리 Hub에 들어오는 HTTP 요청**에 적용됩니다. 현재 탐지는 다음 URL/쿼리 패턴에 한정됩니다.

- `.env`, `.git`, `wp-admin`, `wp-login.php`, `phpmyadmin` 등 Hub가 제공하지 않는 민감 경로 탐색
- `<script>`, `UNION [ALL] SELECT`, prototype 변경 형태의 명확한 URL 패턴
- 인코딩된 `../` 등 경로 이탈과 NUL 패턴

검사 입력은 최대 8KiB, percent decoding 최대 2회로 제한합니다. 비밀번호·세션·본문을 탐지 기록으로 수집하지 않습니다. 본문에는 기존 JSON 형식·4KiB 제한·파라미터 SQL·역할·Origin 검사를 계속 적용하지만, 본문 전체의 악성 의미를 분류하는 WAF는 아닙니다. 임의의 400/401 오류나 User-Agent만으로 차단하지 않습니다.

## 차단 정책

1. 첫 위험 요청: IP별 누적 1회, 5분 차단.
2. 차단 중 요청: 기존 차단을 반환하고 횟수나 시간을 늘리지 않음.
3. 5분 만료: 별도 작업 없이 정상 요청 허용. 이후 위험 요청이 들어오면 다음 위반을 누적.
4. 1~5번째 위반: 각각 5분 임시 차단. 6번째 위반: 블랙리스트, 관리자 검토 후 수동 해제.

위반 횟수·만료 시각·블랙리스트는 PostgreSQL에 보관해 재시작으로 초기화되지 않습니다. 동시 요청에도 한 차단 기간에 한 번만 누적하도록 DB 행 잠금과 조건부 upsert를 사용합니다. 횟수는 관리자가 초기화하기 전까지 유지합니다. 단순 대기 만료는 횟수 초기화가 아닙니다.

차단 응답은 6개 언어의 경고를 반환합니다. 임시 차단은 HTTP 429와 `Retry-After`, 블랙리스트는 HTTP 403입니다. 일반 브라우저 방문에는 HTML 경고, API에는 `THREAT_BLOCKED`/`IP_BLACKLISTED` JSON을 반환합니다. 보호 상태를 DB에서 확인하지 못하면 HTTP 503으로 요청을 처리하지 않습니다. 데이터가 없는 `/api/health` liveness만 예외입니다.

## IP 신뢰 경계와 실행

보호 기능은 `scripts/serve.ts`에서 실제 TCP 소켓 `remoteAddress`로 동작합니다. `npm run dev`와 `npm start`는 이 서버를 사용합니다. **`next start`만 직접 실행하거나 서버리스 배포로 바꾸면 이 앞단 보호가 적용되지 않습니다.** 현재 별도 서버리스/WAF 배포 연동은 미구현입니다. 기본 바인딩은 127.0.0.1이며 외부에 자동 공개하지 않습니다.

직접 접속에서는 `X-Forwarded-For`, `X-Real-IP`, 사용자가 보낸 IP 헤더를 믿지 않습니다. IPv4-mapped IPv6를 정규화합니다. 역방향 프록시를 실제로 운영할 때만 다음 항목을 설정합니다.

- `TRUSTED_PROXY_IPS`: 직접 연결되는 프록시의 정확한 IP 목록. CIDR은 지원하지 않음.
- `WEBGUARD_PROXY_SECRET`: 로컬에서 관리하는 32~256자 비밀. 저장소에 실제 값을 넣지 않음.
- 프록시는 `X-WebGuard-Client-IP`와 `X-WebGuard-Proxy-Token`을 덮어써 전달해야 함. 신뢰한 연결 IP와 비밀이 모두 일치해야 클라이언트 IP를 채택.

잘못된 프록시 설정은 신원 확인 실패로 처리합니다. 일반 XFF만으로 임의 IP를 차단할 수 없습니다. 게이트웨이 토큰은 Next.js로 넘기기 전에 제거합니다.

IP는 접속 네트워크 식별 정보이며 실제 사람·공격자의 신원을 증명하지 않습니다. 역공격, 외부 시스템 침입, 신원 역추적은 하지 않습니다. 공유 IP에는 다른 사용자도 있을 수 있으므로 탐지 코드와 차단 기록을 관리자가 검토할 수 있게 합니다.

## 관리자 확인·복구

관리자 대시보드에 최근 50개 IP 기록, 누적 횟수, 임시 차단·블랙리스트·만료 상태와 탐지 분류를 표시합니다. 새 기록은 대시보드 갱신 때 반영되며 실시간 알림 push는 미구현입니다. viewer/analyst의 대시보드 응답에는 IP 목록을 포함하지 않습니다. 이벤트에는 고정 분류만 저장하고 원본 URL·본문·헤더를 남기지 않습니다.

오탐이나 자기 IP 차단 시 프로젝트 폴더의 터미널에서 로컬 관리자 권한으로 해제합니다. migration 환경 파일의 기존 DB 계정을 사용하며 새 비밀번호를 코드에 넣지 않습니다.

```powershell
npm run security:unblock -- 127.0.0.1
```

실제 해제할 IP로 바꾸세요. 해당 IP의 횟수를 0으로 초기화하고 `ip_unblocked` 감사 이벤트를 남깁니다. 과거 감사 이벤트를 지우지 않습니다. IP 기록의 자동 보존 기간 정리·사용자별 이의제기 UI·외부 방화벽·DDoS 대응·봇 판별은 미구현입니다.

## 검증

임시 DB 통합 테스트에서 실제 소켓 IP 차단, 위조 헤더 무시, 동시 요청의 중복 누적 방지, 5분 만료 후 정상 접근, 6번째 블랙리스트, 관리자 해제와 IP 목록 권한을 검증합니다. 5분 경과는 임시 DB 만료 시각만 이동시켜 시험하므로 실제 사용자 IP를 차단하거나 25분을 기다리지 않습니다. 운영 DB에 가짜 공격 기록을 넣지 않습니다.
