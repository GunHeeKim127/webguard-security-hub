# 정식 사이트 검토·수정·교차 검증 — 2026-10-22

대상: https://webguard-security-hub.vercel.app/workbench 및 같은 코드의 격리된 로컬 production 빌드. 1단계 완료·2단계 진행 중을 유지한다. 확인하지 않은 플랫폼·검사를 완료로 올리지 않는다.

## 실제 정식 화면 확인

사용자가 직접 관리자 로그인한 브라우저에서 홈의 선택 버튼, Endpoint/Mobile 전용 URL, 준비 중 버튼, Linux 설정의 판정·개선안·재검증·다운로드를 확인했다. 계정 비밀번호를 읽거나 변경하지 않았다.

- 별도 `Verification SSH 20261022` 자산으로 합성 위험 설정을 진단해 경고 5개, 같은 자산의 개선 설정으로 기본 통과 5개·개선 관찰 5개·악화 0개를 확인했다. 이전 실행은 유지됐다.
- 실제 내려받은 `velthara-assessment-v1` JSON의 5개 통과·5개 개선을 화면과 대조했다. 원문 설정·비밀번호 해시가 없는 것을 확인했다.
- 잘못된 Linux 입력은 거절됐고 기존 성공 결과는 남았다. 다만 웹 DNS/HTTPS 오류 안내가 나오는 문제를 재현했다.
- 설정을 수정해도 이전 분석 동의가 남는 문제를 재현했다.
- 모바일 IPA는 선택만으로 읽지 않으며 동의 후 Worker 요약이 생성됐다. 첫 시도는 실패했고 두 번째는 성공했다. 브라우저 로그에는 원인 진단 정보가 없어 첫 실패의 근본 원인을 확정하지 않았다.
- 보호 단계의 `PROTECTION_UNAVAILABLE`을 실제로 관찰했다. 이후 같은 요청이 입력 검증까지 도달해 거절된 것을 확인했다. 해당 오류는 앱 입력 오류나 계정 권한 문제와 구분한다.

사용자의 후속 지시에 따라 이후 파일 검사는 **격리된 로컬 환경에서만** 수행했다. 테스트 파일 원본은 정식 서버에 업로드하지 않았다. 앞서 저장한 정식 Linux 합성 진단 2개는 위 이름의 별도 자산 이력이며 기존 자료와 구분해 보존했다. 정식 모바일 요약 저장 요청은 보호 오류로 거절됐고 성공 저장으로 기록하지 않는다. 기존 사용자 자료를 삭제하거나 정리하지 않았다.

## 수정한 동작

1. **입력과 동의:** 주소·자산 이름·설정 내용을 바꾸면 분석 동의를 해제한다. 설정 파일 읽기마다 별도 순서를 부여해 늦은 읽기가 새 파일·수동 입력·샘플 선택을 덮어쓰지 않게 한다. 크기 초과/읽기 실패 선택은 이전 설정을 비운다. 전송 중 입력을 잠그며 버튼과 Enter 제출에 같은 조건을 적용한다.
2. **필수 파일:** 파일 없이 점검을 누르면 파일 선택 오류를 표시한다. 읽기 허용 체크는 파일 선택 전 비활성이다. 선택 후 미동의 상태에서는 읽지 않으며, 빈 파일은 명시적으로 거절하고 허용을 초기화한다. 파일이 없어도 자동 샘플을 대신 읽지 않는다.
3. **경고 가시성:** 결과 상단에 개선·검토 필요 개수와 미검사 개수를 표시한다. 위험 선언은 warning/검토 필요와 위험도·개선 방법을 유지한다. 관찰 정보는 info, 확인할 수 없는 내용은 not_assessed로 구분한다. 경고가 없다는 이유로 전체 안전을 표시하지 않는다.
4. **맞는 오류 안내:** Linux/Windows 설정·파일 요약 입력 실패는 검사 종류·자산 이름·설정/파일 형식을 확인하도록 안내한다. 공개 웹 검사만 DNS/HTTPS 실패 안내를 사용한다. 6개 언어 오류 문구를 추가했다. Worker 자체의 시작/실행 실패도 손상 파일 오류와 구분한다.
5. **제한된 요청 복구:** assessment 조회/저장에서 HTTP 503 + 정확한 `PROTECTION_UNAVAILABLE` 응답만 300ms 후 한 번 재시도한다. 이 응답은 보호 단계가 API 실행 전에 반환한다. 차단·권한 거절·일반 503·네트워크 예외·잘못된 응답은 재시도하지 않는다. 취소 시 대기와 재요청을 중단한다. DB 보호를 건너뛰거나 성공 여부가 불명확한 쓰기를 반복하지 않는다.
6. **Windows 검증 경로:** 한글 경로에서 임시 PostgreSQL 초기화가 실패해 클러스터 위치를 Windows 임시 디렉터리로 분리했다. `PG_TEST_ROOT`로 지정할 수도 있다. 바이너리 또한 ASCII 경로를 사용했다. 테스트용 환경 파일은 기존 보안 제한대로 프로젝트의 Git 제외 work/에만 생성한다.

요청 재시도는 일시 실패에 대한 제한된 복구이며 제공자 DB 장애의 근본 원인 해결을 증명하지 않는다. 반복 실패는 계속 오류로 남기며 운영 로그 대조가 필요하다.

## 수정본의 실제 브라우저 검증

운영 DB와 분리된 임시 PostgreSQL 17.5·임시 관리자/viewer 및 loopback 앱을 사용했다. Node.js 24.19.0 / Next.js 16.4.2, 별도 `.next-verify` 빌드다.

| 사례 | 실제 결과 |
|---|---|
| 파일 없음 | `검사할 파일을 먼저 선택해 주세요.` 표시, 요약/저장 없음 |
| 선택했지만 읽기 미동의 | 점검 비활성, 자동 읽기/분석 없음 |
| 빈 EXE | 빈 파일 안내, 동의 초기화, 요약/저장 없음 |
| 손상 EXE | 지원하지 않거나 손상된 파일로 거절, 요약/저장 없음 |
| PE 구조 정상·보호 선언 위험 | Worker 완료, 별도 동의 후 로컬 DB 저장, ASLR/NX/W+X 경고 3개·서명 미검사 1개 |
| IPA 구조 정상·광범위 HTTP 허용 명시 | Worker 완료·요약 저장, 경고 1개·미검사 3개 |
| 설정 변경 | 기존 동의 false·진단 버튼 비활성 |
| 64 KiB 초과 설정 선택 | 크기 오류·이전 설정 제거·동의 해제 |

합성 EXE/IPA는 파서용 최소 구조이며 설치·실행 가능한 실제 애플리케이션이라는 의미가 아니다. 테스트 파일·임시 계정 도구·DB·화면 증거는 work/ 또는 별도 임시 경로에만 두고 Git/배포물에는 넣지 않는다. 실제 사용자는 본인이 선택한 파일을 읽기 허용 후 검사한다.

화면 증거: Git 제외 `work/verified-warning-summary.jpg`. 테스트 파일 경로를 제품 코드에 고정하거나 샘플 결과를 실제 검사처럼 보여주는 기능은 추가하지 않았다.

## 자동 검사와 교차 검증

- **98개 단위·회귀 테스트 통과.** 추가 항목은 위험 선언의 warning 유지, 보호 오류만 1회 재시도, 취소 시 재시도 중단, 설정 입력 오류의 6개 언어 안내다.
- 최종 Next.js webpack production 빌드·독립 TypeScript 검사·보안 HTTP smoke·6개 언어 HTTP smoke 통과.
- 독립 DB/실제 HTTP 통합 통과: migrations·앱 최소 권한·가입 viewer 강제·계정별 자산/결과·다중 세션·로그아웃·CSRF·SSRF·실패 보존·불변 재검증 이력·집계 키·IP 보호·AI 로컬 모형·이전/복구. 새 입력 오류 코드와 기존 성공 실행 보존도 검사했다.
- 같은 결과를 **파서/규칙 테스트 → 실제 API/DB → 실제 브라우저 → 내려받은 JSON**으로 대조했다. 수정 diff·Git 제외 규칙과 테스트 파일이 app/lib/public에서 참조되지 않는 것도 검토했다.

실제 Kali SSH 유효 정책, Mac OS 도구, 실물 모바일 앱 설치·실행·서명 신뢰, 준비 중 엔진, 외부 AI 실호출·완전한 침투/부하 검사는 이 결과에 포함되지 않는다. Tera Term은 사용자가 제공한 후속 화면에서 이미 인증된 root SSH 세션임을 확인했다. 별도 자동 SSH 연결의 키 인증 실패와 사용자의 기존 연결 성공을 혼동하지 않는다.

## Git 반영 후 확인할 범위

Git 업로드 뒤 자동 배포 상태와 정식 사이트의 파일 미선택 오류·초기 동의/저장 상태를 다시 확인한다. 이 단계에서는 테스트 파일을 정식 사이트에 다시 선택하거나 검증 기록을 추가하지 않는다. 코드·테스트 파일 검증과 실제 배포 완료는 구분한다.
