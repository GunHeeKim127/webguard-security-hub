IPA 보완 후 경고 1→0·미검사 3을 유지했다. AAB/APKS/XAPK는 목록 검사만 지원하므로 두 변형 모두 미검사 6이다. 보완 파일도 안전 인증/pass로 표시하지 않는다.

전체 자동 회귀는 **178개: 통과 177 / 실패 0 / 건너뜀 1**이다. 폴더 링크 생성 제약으로 1개가 건너뛰어졌으며 통과에 합산하지 않았다. 타입 검사 통과. 기존 production 빌드·클라이언트 경계 검증도 통과했다. 이번 제품 진단 소스·로그인 화면·테마는 변경하지 않았고, 더미 생성기·테스트·npm 명령·문서를 추가했다.

## 다음 PC에서 시작하기

1. `git status`로 현지 변경을 보존하고 최신 main을 받는다. 이 문서와 AGENTS.md를 먼저 읽는다. 앱 코드를 바꿀 때 설치된 Next 문서도 읽는다.
2. 저장소 lockfile에 맞춰 의존성을 설치한다. `.env*`·실제 키/DB 비밀번호는 Git에서 받는 대상이 아니다. 현지에서 별도로 준비하고 채팅·명령 출력에 노출하지 않는다. 환경변수 설명은 기존 설정/배포 문서를 따른다.
3. `npm test`, `npm run typecheck`를 실행한다. 모바일 더미는 `npm run fixtures:mobile`, `npm run test:mobile:fixtures`로 재현할 수 있다. 더미는 격리 환경에서만 사용하고 운영에 가짜 결과를 저장하지 않는다.
4. 아래 잔여 작업 중 해당 PC에 환경이 있는 항목을 선택한다. 이미 확인한 APK/합성 검증을 이유 없이 반복하거나 2단계 전체를 완료 처리하지 않는다.

검증 서버·임시 DB·가상기기는 종료했다. 해당 PC의 로컬 시험 세션/계정/포트가 다른 PC에 따라오는 것은 아니다. 새 시험은 별도 임시 환경에서 준비한다.

## 남은 작업과 우선순위

- **R01 운영 보호/DB 장기 안정성:** 요청 시각·서버/제공자 지표를 대조하고 휴면 뒤 첫 요청·정상 사용자 저장/조회 복구를 기간을 정해 검증한다. 로컬 성공이나 health 200만으로 끝내지 않는다.
- **R02 관리형 DB 권한/복구:** 제공자 권한·비밀 유출 영향 범위·별도 환경의 실제 백업 복원·고객별 접근 분리·RPO/RTO를 확인한다. 운영 DB를 덮지 않는다.
- **실제 파일/플랫폼:** 허가된 실제 AAB/APKS/XAPK의 구조 대조, 실물 Android/Safari/iOS와 큰 파일 실행 중 취소 계측은 남아 있다. iOS Simulator는 Mac/Xcode 환경이 필요하며 Android Studio로 대체하지 않는다.
- **Mac:** DMG 재실행 성공은 담당자가 이미 회신했다. PKG 실환경·개별 서명/Gatekeeper/entitlement 근거 대조는 별도다. 기존 DMG 오류를 계속 미해결로 표시하지 않는다.
- **환경별 추가 검증:** 이미 확인한 Windows/SSH·GNS3 2.2.61 범위는 보존한다. 추가 Linux 조건·VM 실제 공유 격리·실제 장비 정책은 해당 환경과 근거가 있을 때만 추가한다.
- **R03/R04:** 남은 CSP 스타일 완화와 공유 NAT/한도의 정상 사용자 영향을 실제 환경에서 검토한다.

Cloud·IoT·Container·작업 예약·정식 보고서/새 모듈 AI 등 준비 중 기능을 이번 검증 완료에 포함하지 않는다. 지원 확장 개발과 현재 지원 항목 검증은 분리한다.

## Git에 포함한 것과 이 PC에만 남긴 것

- 포함: 소스 테스트·합성 파일 10개·생성기·해시/집계 증거·문서. 합성 패키지는 설치할 수 없는 시험 입력이며 실제 고객 앱이 아니다.
- 제외: `.env*`, 개인키/서명키, 실제 APK·Manifest, 실제 결과 원문, 캡처, 도구 다운로드/SDK/JBR, 임시 DB, node_modules, 빌드 캐시, ignored work.
- 이 PC의 Android Studio/SDK 업데이트와 Java 인증서 조치는 소스 pull로 다른 PC에 설치되거나 적용되지 않는다. 도구 버전/지원 정책을 현지에서 별도로 확인한다. Android Studio가 웹 서비스 실행에 필요한 것은 아니다.

이번 검증은 격리 로컬 환경이었다. Git push와 Vercel의 실제 배포 성공·운영 검증은 구분해야 한다. 연동된 자동 배포가 실행되더라도 새 배포의 실제 상태는 별도로 확인한다.
