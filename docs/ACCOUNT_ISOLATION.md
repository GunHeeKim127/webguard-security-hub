# 계정별 진단 데이터 분리

변경 기준: 2026-10-17. 이전의 조직 공유 대시보드 대신 **로그인한 계정 자신의 진단과 활동만** 제공합니다. admin도 다른 계정의 진단을 자동 열람하지 않습니다. 관리자의 IP 방어 목록은 서비스 운영용 공통 정보로 유지합니다.

## 적용 범위

- 대시보드의 진단 목록·저장 개수·최근/집계 이벤트에 세션에서 확인한 `user_id`를 적용합니다. 요청 본문의 사용자 ID를 소유자로 채택하지 않습니다.
- AI의 결과 조회는 `scan.id`와 현재 `user_id`를 함께 확인합니다. 다른 계정 ID와 존재하지 않는 ID는 모두 404이며 외부 제공자에 전송하지 않습니다. AI 비활성 여부보다 소유권 확인을 먼저 수행합니다.
- 같은 주소의 최신 결과는 **동일 계정 안에서만** 덮어씁니다. 다른 계정의 같은 도메인은 별도 ID·결과·시각을 가집니다. 소유자 변경 upsert는 제거했습니다.
- AI 캐시 키에 계정을 포함해 같은 모델·언어·헤더 결과라도 다른 계정의 캐시를 재사용하지 않습니다. 기존 공용 캐시는 새 경로에서 참조하지 않습니다. 제공자의 장애/한도 대기는 서버 키 단위 공통 정책입니다.
- 로그인 성공·계정에 대응하는 로그인 실패·가입 요청·진단 완료/거절·AI 생성에 계정 ID를 기록합니다. 익명 공격/디코이·과거 소유자 없는 이벤트는 NULL을 유지하고 개인 활동 API에서 제외합니다.
- 로그아웃·세션 만료·다른 탭의 계정 변경 시 화면의 결과·대상 주소·현재 로그·개선안을 초기화합니다. 이전 계정에서 시작한 늦은 대시보드/AI 응답도 적용하지 않습니다. 최신 브라우저에서는 비밀정보 없는 BroadcastChannel 알림으로 탭 사이 변경을 동기화합니다.

## DB 변경과 기존 데이터

일반 PostgreSQL은 `006_account_isolation.sql`, Prisma는 `prisma-postgres/002_account_isolation.sql`을 추가했습니다. 과거에 적용된 migration 파일은 바꾸지 않습니다.

1. `(user_id,hostname)` 복합 유일성 제약을 추가하고 기존 전역 hostname 유일성만 제거합니다.
2. 이벤트에 nullable user_id와 사용자/시간 인덱스를 추가합니다.
3. 기존 진단 행의 ID·user_id·결과·시각은 그대로 보존합니다. 즉 현재 남아 있는 결과는 마지막 진단자의 계정에 속합니다.
4. 과거 전역 덮어쓰기로 이미 사라진 다른 사용자의 예전 결과는 이 변경으로 복원할 수 없습니다. 사용자를 추측해 결과를 복제하거나 소유권을 옮기지 않습니다.
5. 과거 이벤트에는 신뢰할 계정 정보가 없으므로 개인 기록으로 임의 배정하지 않습니다.

로컬은 `npm run db:migrate` 다음 `npm run db:grant`를 사용합니다. 일반 PG 앱 역할의 scans.user_id UPDATE 권한도 회수합니다. Prisma는 `npm run db:migrate:production`을 사용하며 지원하지 않는 GRANT/REVOKE를 실행하지 않습니다. 변경된 schema가 없으면 readiness는 준비 실패로 반환합니다. 서비스 갱신 중 기존 진단 쓰기는 잠시 실패할 수 있으므로 migration과 새 앱 배포를 함께 진행합니다.

## 검증 기준

- 두 계정에 서로 다른 주소와 같은 주소를 함께 저장하고 목록·개수·원자적 덮어쓰기·동시 갱신이 각각 분리되는지 확인합니다.
- admin/analyst 사이의 상대 결과 ID AI 요청이 404이고 제공자 호출이 없는지 검사합니다.
- 두 계정이 동일한 헤더 결과로 AI를 요청해도 캐시를 공유하지 않는지 확인합니다.
- 계정별 이벤트·최근 이벤트와 소유자 없는 과거 이벤트의 비노출을 검사합니다.
- Prisma용 migration 전의 결과 ID와 소유자, 과거 이벤트 보존을 확인합니다.

분리는 **서버 API의 소유권 검사**입니다. 공통 DB 자격증명에 사용자별 RLS/독립 DB를 새로 제공한 것은 아닙니다. 키 탈취·서버 코드 실행 권한을 얻은 공격자에 대한 DB 수준의 계정 격리를 보장하지 않습니다. 조직/팀 공유·위임·관리자 강제 열람 UI도 별도 기능입니다.

기준: [OWASP 객체별 권한 검사](https://api-security.owasp.org/editions/2023/en/0xa1-broken-object-level-authorization/), [PostgreSQL 복합 유일성 제약](https://www.postgresql.org/docs/current/ddl-constraints.html).

2026-10-17 실제 적용 확인: 로컬/Prisma migration과 기존 데이터 보존 검증을 완료했습니다. 정식 Vercel 사이트에서 임시 admin/analyst의 빈 초기 기록·동일 주소별 개별 결과·자기 결과만 덮어쓰기·목록/개수/이벤트 분리·상대 결과 AI 404·로그아웃 후 401을 확인했습니다. 테스트 데이터만 정리했습니다. 외부 AI 비활성 설정은 유지했으며 캐시 비공유는 가짜 제공자를 사용하는 통합 테스트에서 검증했습니다.
