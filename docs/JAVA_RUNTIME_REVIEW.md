# Java/JVM · Java4Shell 점검

Java4Shell은 CVE-2026-114938이며 JVM의 특정 x86-64 Base64 최적화 경로에 관한 취약점입니다. Log4Shell·JavaScript와 구분합니다. 2026-11-19에 Oracle·CISA·CERT-EU 공지를 대조했습니다.

## 어디서 점검하나요?

기본 분류는 **Endpoint의 Java/JVM 실행 환경**입니다. 검사 선택과 Endpoint 화면의 **Java/JVM · Java4Shell 점검** 버튼으로 `/workbench/java`에 들어갑니다. Java 웹 서버도 같은 점검을 사용하도록 웹 화면에 연결했습니다.

웹 URL이나 Tomcat·Spring 표시만으로 JVM 버전·공급자·CPU·실효 실행 설정을 알 수 없습니다. 웹 진단에서 Java 기술 흔적을 관찰하면 적용 여부를 **미검사**로 표시하고 JVM 자료를 안내합니다. Java가 숨겨져 있다면 헤더에 표시되지 않을 수도 있습니다.

## 사용 순서

1. 대상 JVM의 버전·공급자·아키텍처·CPU 기능·Base64 intrinsic·외부 입력 경로를 확인합니다. 모르는 값은 그대로 미확인으로 둡니다.
2. 점검 권한과 자료 분석에 동의한 뒤 적용 여부를 점검합니다. 기기에 접속·설정 변경·공격 입력 전송·JVM 실행을 하지 않습니다.
3. 버전 대조와 미확인 조건, 공급자 수정·재시작·재확인 안내를 검토합니다. 입력을 바꾸면 결과와 동의를 초기화합니다. 결과는 JSON으로 내려받습니다.

자료·결과는 DB에 저장하거나 외부 AI에 전송하지 않습니다. 일반 계정도 자기 요청으로 검사할 수 있으며 API는 로그인·동일 출처·명시 동의·요청 한도·본문 크기를 확인합니다. 이 화면의 결과는 기존 자산 이력에 자동 저장되지 않습니다.

## 무엇을 구분하나요?

- **영향 버전 가능성·업데이트 권고**: 제공한 버전이 검토한 범위와 일치합니다. 실제 악용 가능성·감염 확정이 아닙니다.
- **버전 기준 충족**: 숫자 버전이 알려진 공통 수정 기준 이상입니다. 공급자 백포트·실제 적용·재시작·전체 안전성을 인증하지 않습니다.
- **추가 자료 필요**: 형식·공급자·범위가 불명확하거나 일부 조건을 확인하지 못했습니다. 빈 값·알 수 없는 버전을 안전으로 처리하지 않습니다.
- ARM64·미지원 CPU 기능·intrinsic 비활성·입력 경로 없음으로 제공된 자료가 있더라도 구형 JVM 업데이트 권고를 숨기지 않습니다. 사용자 제공 자료는 독립 검증 결과가 아닙니다.

공통 숫자 기준은 17.0.21.1, 21.0.13.1, 25.0.5.1, 27.0.1.1입니다. 17.0.21.0.3 등 이전 보안 접미사를 이번 수정과 혼동하지 않습니다. Oracle Java 8 Performance Pack은 8u513 기준을 별도로 다루며, 일반 Java 8과 구분합니다. GraalVM·JBR 등 공급자 고유 버전은 무리하게 같은 표에 대응시키지 않고 업체 공지를 요청합니다. Java 11·구형 Java가 이 CVE 범위와 다르더라도 다른 Java 취약점에 안전하다는 뜻은 아닙니다.

## 확인·해결 방법

신뢰하는 설치본에서 `java -version`을 확인하되 PATH의 Java와 실제 서비스·컨테이너·IDE 번들 JVM을 구분합니다. 서버 담당자가 대상 프로세스의 실제 JVM·CPU·실효 옵션을 확인해야 합니다. 새로운 JVM을 실행해 본 기본 옵션만으로 기존 프로세스 설정을 증명할 수 없습니다. 전체 명령행에는 비밀번호가 포함될 수 있으므로 제출하지 않습니다.

공급자의 해당 CVE 수정 릴리스 또는 번들 제품 업데이트를 우선 적용하고, 프로세스를 재시작한 뒤 실제 사용 버전을 재확인합니다. 임시 intrinsic 완화는 공식 공지와 배포판 지원·성능 영향을 검토해야 합니다. ARM에 x86 전용 UseAVX 옵션을 적용하지 않습니다. 서비스 설정은 자동 변경하지 않습니다.

## 함께 수행한 자체 보안 보완

구현 중 기존 Next.js 16.4.2의 보안 경고를 확인해 같은 16.4 계열의 16.4.6으로 갱신했습니다. 운영 의존성 감사에서 발견된 전이 의존성 경고는 `@vercel/functions` 3.11.3 업데이트로 해소했습니다. `@next/env`도 대응 버전으로 맞췄고 설치 스크립트는 실행하지 않았습니다. 설치·감사는 HTTPS 레지스트리로 수행했습니다. 인증정보를 포함할 수 있는 npm 로컬 설정은 기존 제외 규칙에 따라 Git에 포함하지 않습니다.

최종 `npm audit --omit=dev` 조회에서는 알려진 운영 의존성 취약점 0건이 반환됐습니다. 이는 해당 시점의 공개 감사 범위이며 새 취약점·미공개 문제·기능 적용 상태까지 안전하다는 보증은 아닙니다.

## 검증 기록 · 2026-11-19

최종 전체 테스트 240개, 타입 검사·운영 빌드·클라이언트 경계 검사를 통과했습니다. 실제 사용자 DB와 분리된 임시 환경에서 비로그인 401·다른 출처 403·동의 누락/잘못된 값 400·정상 버전 점검 200을 확인했습니다.

브라우저에서 시험 계정 로그인 → 검사 선택의 Endpoint Java 버튼 → 버전·공급자 입력 → 동의 → 영향 버전 업데이트 권고를 확인했습니다. 수정 버전으로 변경할 때 기존 결과·동의가 초기화되고, 다시 동의한 뒤 숫자 기준 충족과 CPU 등 미확인 조건이 함께 표시되는 것도 확인했습니다. 실제 공격·JVM 실행·제품 자동 업데이트는 수행하지 않았습니다.
