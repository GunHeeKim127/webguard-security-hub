# 반복 가능한 논리 백업·복원 검증

`scripts/verify-recovery.ts`는 기존 운영 migration 설정과 `PG_BIN`으로 지정한 PostgreSQL 도구 폴더를 사용합니다. `pg_dump`, `pg_restore`, `initdb`, `pg_ctl`이 모두 필요하며 원본 서버를 읽을 수 있는 버전이어야 합니다. Windows에서는 로컬 PostgreSQL 서버를 실행할 수 있는 일반 사용자 환경이 필요합니다.

1. 운영 migration 설정을 로컬에서 준비하고 `PG_BIN`에 도구 폴더의 절대 경로를 지정합니다. 비밀 값은 채팅이나 저장소에 넣지 않습니다.
2. `npm run db:verify-recovery:production`을 실행합니다. 운영 DB에는 읽기 전용 단일 스냅샷만 사용하고, 임시 암호 인증 loopback DB에만 복원합니다.
3. 성공 JSON의 테이블 내용 일치·소유 관계·일반 권한 조회 거절과 `cleanupComplete`를 확인합니다. 자체 복원 서버가 중지된 후에만 성공 결과를 기록합니다. 실패하면 완료로 처리하지 않습니다.

백업과 검증 결과는 실행마다 새로 만든 `work/private-recovery-*`에 저장합니다. Windows에서는 현재 사용자 전용 ACL, 다른 OS에서는 소유자 전용 폴더 권한을 적용한 뒤 파일을 씁니다. 운영 백업에는 개인정보와 세션 데이터 등이 포함될 수 있으므로 이 폴더를 업로드하거나 공유하지 마세요. 검증 후 자체 복원 서버는 중지하고 백업은 로컬에 남깁니다. 별도 보관 기한·보호된 오프라인 저장소·운영 담당자의 정기 실행 정책은 추가로 정해야 합니다.

이 도구는 운영 복원을 수행하지 않습니다. 원래 제공자의 역할·권한 복원, PITR, 장애 시 목표 복구 시간·데이터 손실량, 백업 파일 암호화나 원격 보관까지 보장하지 않습니다. 실제 장애 복원은 격리 사본에서 확인한 뒤 별도 변경 절차로 진행해야 합니다.

2026-11-04 실제 운영 백업의 조치·변경 이력을 포함한 15개 테이블을 복원하여 행 수·내용 지문과 소유 관계를 확인했습니다. 운영 쓰기는 없었으며 전체 논리 복구 시험 약 36초는 운영 복구 시간 보장이 아닙니다.
