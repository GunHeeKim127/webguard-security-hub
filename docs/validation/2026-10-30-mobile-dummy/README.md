# 모바일 더미·실제 사용자 순서 검증 — 2026-10-30

**더미 검증 완료:** IPA·AAB·APKS·XAPK 취약/보완 합성 파일 8개와 거부 입력 2개를 준비하고, PC 브라우저의 실제 파일 선택·동의·검사·저장·비교·다운로드를 수행했다. 4개 자산·8개 실행 보고서가 기대 결과와 일치했고, 형식별로 다운로드한 JSON의 전체 report가 DB 조회값과 일치했다. 잘못된 두 입력은 거부되고 저장되지 않았다. [기계 판독 증거](evidence.json), [독립 ZIP/plist 대조](independent.json).

## 실제 사용 순서

1. 격리된 로컬 시험 사이트에서 일반 시험 계정으로 로그인하고 Mobile 버튼으로 모바일 진단 작전실에 이동한다.
2. 자산 이름을 입력하고 실제 파일 선택기로 취약 선언 더미를 선택한다. 읽기 동의 전 검사 비활성 및 별도 분석 동의 전 저장 비활성을 확인한다.
3. 읽기에 동의→기기 내 점검→원본 미전송/요약 확인→별도 소유·분석 동의→저장을 수행한다. 같은 자산 이름으로 보완 파일도 반복하고 결과 비교를 확인한다. 저장한 자산을 목록에서 다시 선택하고 JSON을 다운로드한다.

모든 긍정 입력은 UI 파일 선택기와 검사 버튼을 통과했다. API에 준비된 결과를 직접 넣어 사용자 흐름 검증을 대체하지 않았다. 이후 API는 UI가 저장한 결과를 읽어 대조하는 데 사용했다. 합성 파일 이름은 검사 후 서버 요약에 포함되지 않는다.

## 관찰 결과

| 형식 | 취약 선언 | 보완 선언 | 유지되는 한계 |
|---|---|---|---|
| IPA | HTTP 허용 경고 1, 미검사 3 | 경고 0, 미검사 3 | 서명·코드·중첩 앱 미검사 |
| AAB | 경고 0, 미검사 6 | 경고 0, 미검사 6 | protobuf 설정은 읽지 않음 |
| APKS | 경고 0, 미검사 6 | 경고 0, 미검사 6 | 중첩 APK는 분석하지 않음 |
| XAPK | 경고 0, 미검사 6 | 경고 0, 미검사 6 | 중첩 APK/실효 정책 미검사 |
| 경로 탈출 ZIP | 확인 불가 안내·저장 비활성 | 해당 없음 | 경로를 추출하거나 실행하지 않음 |
| 텍스트를 .ipa로 변경 | 확인 불가 안내·저장 비활성 | 해당 없음 | 확장자만으로 신뢰하지 않음 |

보완 파일의 경고 감소는 전체 안전 인증이 아니다. IPA의 보완 선언은 info이며 pass가 아니다. 실제 비교 UI는 IPA에서 변경 2(설정과 패키지 크기), 비교 불가 3을 표시했다. AAB/XAPK도 크기 등 목록 차이가 변경으로 표시될 수 있고 APKS는 같은 목록 관찰로 동일 1·비교 불가 6이었다. 미검사→안전으로 승격시키지 않았다. 파일 이름의 vulnerable/remediated는 시험 변형 이름이며, AAB/APKS/XAPK의 내부 위험 설정을 현재 엔진이 탐지한다는 뜻이 아니다.

## 독립 검증과 회귀

Python 3.11의 zipfile.testzip으로 8개 ZIP의 CRC/목록과 중첩 합성 APK를 확인했다. plistlib로 IPA 두 파일의 NSAllowsArbitraryLoads true/false를 별도 해석하고 SHA-256도 대조했다. 새 자동 테스트 6개는 형식 분류·명시값·미검사 유지·잘못된 입력 거부·파일 해시를 확인한다. 전체 npm test: 178개 중 통과 177·실패 0·환경상 폴더 링크 생성 제약으로 건너뜀 1. npm run typecheck 통과. 이전 중단 설치로 없어진 npm 실행 shim은 npm rebuild --ignore-scripts --bin-links로 복구했으며 설치 스크립트나 의존성 버전/lockfile은 변경하지 않았다.

재현 명령: npm run fixtures:mobile → npm run test:mobile:fixtures. [더미 파일 설명](../../../tests/fixtures/mobile-2026-10-30/README.md)과 manifest.json에 파일별 해시·예상 분석이 있다. 생성기는 기존 더미 내용이 다르면 덮어쓰지 않는다.

## 검증 중 문제와 조치

- 브라우저 파일 전달/다운로드 도구의 일부 호출에 수 분 지연이 있었다. 검사 엔진/운영 사이트 지연으로 확정하지 않았고, 선택 완료를 확인한 다음 UI 단계를 진행했다. 영문 경로의 동일 바이트 사본도 사용했다.
- 장시간 검증 중 시험 서버의 40분 종료 시점이 가까워 기존 임시 DB를 보존해 시험 서버만 재시작했다. 저장한 6개 실행을 유지한 상태에서 나머지 검증을 이어갔다. 운영 DB에는 연결하지 않았다.
- 교차 확인 헬퍼가 다운로드에 asset.id가 있다고 잘못 가정했다. 실제 내보내기 계약의 run.asset_id로 수정한 뒤 8개 보고서와 4개 다운로드의 대조를 통과했다. 제품 버그로 기록하지 않는다.

제품 진단 코드를 바꿀 오류는 발견하지 않았으며, 이번 변경은 더미 생성기·검증 테스트·문서·npm 명령이다. 로그인 화면과 기존 테마는 변경하지 않았다.

검증 후 직접 시작한 시험 웹 서버·임시 DB를 종료했다. 더미 파일·원본 결과·캡처는 보존했다. 이 결과가 운영 배포나 상시 시험 서버를 의미하지 않으며 Git 업로드·배포는 수행하지 않았다.

## iOS 도구와 완료 범위

Android Studio의 APK Analyzer는 APK/AAB를 다루며 iOS Simulator를 제공하지 않는다. Apple Simulator는 Xcode에 포함되고 Xcode는 지원되는 macOS 환경이 필요하다. 이번 Windows 브라우저의 IPA Info.plist 정적 검사는 iPhone/Safari·iOS 앱 설치/실행·서명/entitlement/provisioning 검증이 아니다. Xcode나 비공식 iOS 에뮬레이터를 설치하지 않았다.

이 파일들은 설치 가능한 앱이 아니다. AAB Manifest/toc.pb는 합성 표식이며 유효한 protobuf 빌드 산출물이 아니므로 Android Studio/bundletool로 정상 빌드·배포를 증명하지 않는다. 실제 앱 산출물·실물 기기·큰 파일 실행 중 취소·서명 신뢰와 기존 R01/R02 완료는 별도다. **더미/PC 사용자 흐름은 확인 완료, 2단계 전체는 진행 중**이다.

공식 근거: [Google APK Analyzer](https://developer.android.com/studio/debug/apk-analyzer), [Apple Xcode 요구사항](https://developer.apple.com/xcode/system-requirements/), [Apple Simulator 안내](https://help.apple.com/xcode/mac/current/en.lproj/devfd9e28378.html).
