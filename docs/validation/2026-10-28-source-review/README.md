- 자동 회귀 139개, 타입 검사 및 production 빌드 통과.
- 격리 PostgreSQL/HTTP 일반 회원: 소스 검사 비로그인 401, 다른 출처 403, 미동의·빈 입력·지원하지 않는 필드 400, 정상 입력 200. 소스 원문 비반환, 수신 UTF-8 SHA-256, 결과 비저장을 확인했다.
- 일반 회원 브라우저: 파일 미선택 오류, 선택 후 동의 전 비활성, 동의 후 검사와 실제 버전/권고 기준 표시. 소스 전용 검사 범위·해시 안내와 독립 결과 영역도 최종 빌드에서 확인했다.
- 검증 파일은 ignored work/에서만 사용했다. 운영 검사 기본값·저장 자산에는 테스트 파일을 넣지 않았다. [로컬 최종 결과 화면](source-result-local.png).
- 최종 브라우저 번들 소스맵·sourceMappingURL 0개, DB 인증 URL·개인키 고정 패턴 미검출. 로컬 및 운영 소스맵 요청 404·no-store. 이 패턴 검사가 모든 비밀 부재를 증명하지는 않는다.

## GitHub 환경 파일 기록

현재 파일과 과거 Git 기록을 검사했다. 최초 경로 검사는 `.env`로 시작하는 예시만 식별했으나, 원격 새 복제본 교차 검사에서 deploy/의 `*.env.example`도 발견해 범위를 보완했다. 빈 키·예시 자격증명으로 확인됐으며 실제 운영 키와 일치하는 값은 발견하지 못했다. URL이나 비밀 값은 기록에 출력하지 않았다.

사용자의 이력 교체 승인 후 다음 5개 경로와 해당 env 이름 패턴을 main 전체 이력에서 제거했다.

- `.env.example`
- `.env.migration.example`
- `deploy/migration.production.env.example`
- `deploy/prisma.vercel.env.example`
- `deploy/vercel.env.example`

`--force-with-lease`로 반영했고 로컬 main도 작업 파일을 보존해 정리 이력과 동기화했다. GitHub에서 새로 복제한 최종 사본의 main은 84a3cab이며 40개 커밋의 도달 가능한 객체에서 환경 파일 경로가 0개였다. 정리 전후 최신 tree 해시가 같아 최신 코드 파일은 변하지 않았다. 복구 번들과 작업 사본은 ignored work/에만 남으며 업로드하지 않는다. 다른 PC는 옛 이력을 그대로 다시 push하지 말고 새 main에 맞춰 동기화해야 한다.

이는 GitHub main에서 도달 가능한 이력 정리다. 외부 복제본·포크·GitHub의 옛 SHA 캐시나 숨은 참조를 직접 삭제했다는 뜻은 아니다.

## 운영 후속 상태

소스 점검 코드 배포는 success를 확인했다. 운영 재검증 중 readiness 503과 접속 보호 PROTECTION_UNAVAILABLE가 재발했다. Vercel 로그는 block_read 쿼리 시간 초과와 1회 재시도 실패를 보였고, 비밀 값 없는 고정 오류 코드만 확인했다. 같은 시점 이 PC의 직접·풀링 DB 연결 및 SELECT/인덱스 조회는 정상이라, 운영 실행 환경의 간헐 실패가 해결됐다고 단정하지 않는다. 준비 상태의 상세 코드는 공개 응답 대신 서버 로그에만 남기도록 보완한다.
