# 3단계 — 통합 운영·보고서·위협 대응

2026-11-03 시작. [2단계 범위 한정 완료](PHASE2_SUBMISSION.md)는 유지합니다. 베타 피드백에 따른 기존 기능 결함 수정과 신규 3단계 개발을 구분합니다.

## 첫 구현: 읽기용 보고서 초안

내 결과에서 선택한 모듈의 최신 저장 결과를 TXT 보고서 초안으로 내려받습니다. 상태 요약·검사 범위·한계·항목별 관찰·비교 기준·다음 조치·기술 근거를 포함합니다. 기존 JSON 다운로드도 유지합니다. 이미 조회한 자기 결과만 사용하며 새 검사·AI 호출·외부 전송·DB 변경은 하지 않습니다.

미확인 결과를 안전이나 취약점 확정으로 바꾸지 않으며, 조치를 완료했다고 자동 표시하지 않습니다. 계정·자산 식별자·접속키를 새로 추가하지 않습니다. 결과 내용 자체는 공유 전 검토해야 합니다. 정식 심사·인증 보고서, 서명된 문서, PDF, 전체 추세·조치 관리의 완성을 뜻하지 않습니다. 지원 기능은 모듈 결과 화면이며 기존 웹 기본 진단 화면에는 아직 동일 초안 버튼이 없습니다.

## 다음 구현 순서

1. 조치 관리: 본인 자산·결과 항목별 미착수/진행/재검증 필요/종료 상태와 근거를 관리합니다. 사용자 선언과 실제 재검증 성공을 구분하고 다른 계정 변경을 서버에서 거절해야 합니다. DB migration·보관·권한 시험 후 적용합니다.
2. 보고서 확장: 선택 결과·비교 기준·미확인 범위를 일관되게 내보내고 지원 형식과 사용성을 확인합니다. 추세는 호환되는 결과끼리만 계산합니다.
3. 운영 보안: 기존 장기 안정성·보호 오류·실제 복원·DB 권한/키 후속 검증을 이어갑니다. 확인 전 해결로 바꾸지 않습니다.
4. 위협 대응·허니팟: 기존 경고/차단/관리자 해제를 보존합니다. 허니팟은 운영·고객 DB와 분리하고 비밀 미주입·외부 통신 제한·정리/중지·격리 검증을 먼저 설계합니다. 운영 공격 요청을 실습 VM으로 자동 전달하는 기능은 아직 없습니다.

## 베타 피드백 처리

제보 시 아래 항목만 받습니다. 비밀번호·토큰·원본 고객 파일·개인 경로·원본 로그는 공개 이슈나 Git에 넣지 않습니다.

- 사용 화면과 수행 순서
- 기대한 동작 / 실제 동작
- 발생 시각, 브라우저·OS 종류
- 오류 코드와 개인정보를 가린 캡처(선택)
- 재현 여부와 수정 후 재확인 결과

재현 가능한 사용 차단·계정 분리·데이터 보존 문제를 신규 기능보다 먼저 처리합니다. ‘재현 전 → 확인 → 수정 → 회귀 검증 → 사용자 재확인’ 상태로 추적하며, 전달되지 않은 베타 결과를 성공으로 간주하지 않습니다.
