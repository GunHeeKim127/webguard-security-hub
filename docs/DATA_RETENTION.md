# 고객별 데이터와 30일 보관

웹 소스·의존성·SQL 정적 검토는 예외적으로 원문과 결과를 DB에 저장하지 않는다. 동의한 요청의 서버 메모리에서만 처리하며 결과는 현재 브라우저 화면에 표시되고 새로고침하면 사라진다. 따라서 아래 30일 표시/별도 아카이브 정책은 저장되는 진단 기록에 적용되며 소스 검토 원문을 30일 보관한다는 뜻은 아니다.

2026-10-23 기준. 일반 회원·분석가·관리자는 본인의 지원되는 진단 기능을 이용한다. 준비 중 엔진과 관리자 IP 운영 정보는 일반 고객에게 공개하지 않는다.

## 조회 정책

웹 결과·목록·개수·AI 대상은 최근 30일의 본인 진단으로 제한한다. 자산 목록·직접 ID 조회·집계 키 교체/수집도 최근 30일에 갱신한 본인 자산만 허용한다. 실행 이력은 각 실행 시각 기준이다. 다른 고객이나 만료된 자산 ID는 404다. 관리자도 타 고객의 진단을 자동 열람하지 않는다.

같은 웹 주소는 계정 안에서 최신 결과를 갱신한다. 모듈 자산은 계정·모듈·대상 키의 ID를 유지하고 재검증 이력을 추가한다. 이력을 전부 덮어쓰지 않는다. 이미 열린 화면은 재조회 시 반영되며 기존 목록 제한(자산 50개·실행 10개·기존 웹 30개)은 유지한다. 보관 작업 전에도 API의 날짜 필터는 적용된다.

## 보관 테이블

`webguard_archive.diagnostic_records`에 종류·원래 ID·시각·소유 계정 ID·원본 행 JSON·보관 시각을 남긴다. 30일 초과 웹 진단·모듈 실행·트래픽 집계·진단 이벤트가 대상이다. 계정·비밀번호·세션·IP 방어·로그인 감사 기록은 이 작업에서 지우지 않는다. 자산 식별 메타데이터도 유지해 오래된 자산을 재검사하면 같은 ID로 새 결과를 볼 수 있다. 원본 파일을 보관하는 기능은 아니다.

행 잠금 → 보관 INSERT → 활성 테이블에서 이관을 하나의 DB 트랜잭션에서 수행한다. 실패 시 전체 호출을 롤백해 원본을 유지한다. 중복 키·advisory lock·SKIP LOCKED로 재실행과 동시 작업을 처리한다. 보관 테이블의 자동 삭제 기한은 설정하지 않는다.

일반 PostgreSQL은 보관 schema/table을 runtime에 공개하지 않고, 입력 없는 고정 30일 함수만 실행하게 한다. Prisma 프로필은 제공자 계정의 SQL 역할 격리를 보장하지 않으므로 앱 SQL 경계에서 보관 schema 직접 접근을 거절한다. 고객 API와 관리자 웹 세션에 보관 조회 경로를 제공하지 않는다.

## 운영

- Vercel Cron: 매일 00:00 UTC(한국 09:00), `/api/maintenance/archive`.
- 정확한 `CRON_SECRET` Bearer 인증만 허용한다. 계정 로그인으로 대신할 수 없다. 미설정 503, 잘못된 인증 401이다.
- 호출당 테이블별 1,000행, HTTP 작업당 최대 20회/45초다. `complete=false`이면 잠금/상한 때문에 잔여 작업이 있을 수 있다. API 날짜 제한은 계속 적용된다.
- 초기 대량 이관: `node --env-file=.env.migration.production.local node_modules/tsx/dist/cli.mjs scripts/archive-diagnostics.ts`. 비밀 값은 출력하지 않는다. 보관 복원은 별도 운영 DB 작업이며 고객 복원 UI는 없다.

## 검증

임시 DB에서 29일/31일 이상 기록의 API 노출 차이, 보관 전 필터, 고객 간 격리, 보관 테이블 직접 조회 거절, 인증, 보관 INSERT 실패 시 전체 롤백, 원문 보존, 중복 없는 재실행과 같은 자산 재등장을 검사했다.

운영 Prisma migration 005를 적용했고 초기 실행은 `moved=0`이었다. 30일 초과 대상이 없었으며 가짜 운영 자료를 만들지 않았다. 배포 후 정식 경로·Cron·인증 동작은 별도로 확인한다.

Windows/배포 줄바꿈 차이는 내용이 같은 LF/CRLF checksum만 인정한다. 기존 checksum 이력은 변경하지 않고 SQL 내용 변경은 거절한다.
