# GitHub·소스 공급망 검토

검사 선택 화면의 **GitHub·소스 공급망 진단 작전실** 또는 `/workbench/repository`에서 이용합니다. 로그인한 사용자만 검사할 수 있습니다. 기존 웹·모바일·시스템 진단과 별도로 제공하며 로그인 화면은 변경하지 않았습니다.

## 사용 순서

1. 공개 `https://github.com/owner/repository` 주소를 입력하거나, 점검 권한이 있는 텍스트 소스 파일을 선택합니다. 비밀번호·키·환경 파일을 넣지 마세요.
2. 파일 읽기·서버 전송 또는 공개 저장소 조회에 동의하고 **실행 없이 검사**를 누릅니다.
3. 단서의 파일·줄 번호·개선 안내와 검사 제외 범위를 확인하고 결과 JSON을 내려받습니다. 주소·파일 변경 또는 재검사 시 동의를 다시 확인합니다.

## 검사 범위

사용자가 공유한 [데일리시큐 기사 · 2026-11-07](https://www.dailysecu.com/news/articleView.html?idxno=209366)는 아래 Dr.Web 원본 분석과 같은 Trojan.Loader.3261 캠페인입니다. 현재 기능과 기사 내용의 대응 범위는 다음과 같습니다.

| 기사에서 다루는 방식 | 현재 확인하는 내용 | 남는 한계 |
| --- | --- | --- |
| Visual Studio 프로젝트의 빌드 전 명령 | `.csproj`·`.props`·`.targets`의 자동 실행 선언 | 가져오는 파일·실제 빌드 실행 관계는 미검사 |
| Python·Go 소스의 긴 공백 뒤 코드 | 긴 공백·방향 제어 문자·일부 셸 명령 | 압축·난독화·여러 줄/파일의 실행 관계는 놓칠 수 있음 |
| PowerShell 다운로드·보호 기능 변경 | 인코딩·우회 실행, 다운로드-실행 연결, 보호·복구 변경 문자열 | 암호화된 로더·다단계 링크·실제 실행 여부는 미검사 |
| 공개된 통신 지표 | 일부 정확한 도메인·IP 문자열 대조 | 신규 지표·과거 통신·회피된 통신은 미검사 |
| `.suo`·Electron 로더·프로세스 주입 | 이 소스 검사에서는 미검사로 명시 | 바이너리·메모리·EDR 등 별도 분석 필요 |
| AsyncRAT·클리퍼·브라우저/VPN/FTP 정보 탈취 | PC의 일부 흔적·백신 상태를 별도로 확인 가능 | 감염·탈취 부재를 증명하지 못함 |

이번 기사와 동일한 유형을 다루지만, 공격 전체의 탐지·치료 도구는 아닙니다. GitHub Actions·npm 훅 검토는 이 기사 외에도 적용되는 추가 공급망 점검입니다.

- 빌드 자동 명령, npm 설치 훅, 인코딩·숨김 PowerShell, 다운로드와 실행 연결, 보호 기능 변경, 자동 시작 등록, 긴 공백·방향 제어 문자 단서를 정적으로 검토합니다.
- YAML에서 권한 있는 PR 이벤트와 전체 커밋 SHA에 고정되지 않은 Actions를 검토합니다. 실제 YAML 실행 의미와 작업 간 데이터 흐름을 분석하는 것은 아닙니다.
- Dr.Web가 공개한 Trojan.Loader.3261 캠페인의 일부 도메인·IP 문자열과 대조합니다. 문서·주석·시험 데이터도 일치할 수 있으며 일치 자체가 감염의 증거는 아닙니다.
- 공개 저장소는 공식 GitHub API만 사용합니다. 기본 브랜치 커밋을 고정하고 Git blob 해시를 대조합니다. 코드·외부 링크·Release·Git hooks는 실행하거나 다운로드하지 않습니다.
- 원격 조회: 최대 12개 텍스트 파일, 파일당 32 KiB, 합계 256 KiB입니다. 목록 응답은 1 MiB·5,000개 항목까지 허용합니다. 설치·빌드·워크플로 파일을 우선 선택하며 검사·제외 목록과 트리 잘림을 표시합니다. 파일 크기·개수·지원 확장자·심볼릭 링크·UTF-8 조건으로 제외될 수 있습니다.
- 로컬 선택: 최대 30개, 파일당 64 KiB, 합계 512 KiB입니다. 직접 선택한 파일은 기본 파일명으로 구분하므로 같은 이름의 파일은 나눠 검사하세요. ZIP·실행 파일·비공개 저장소·전체 의존성 분석은 지원하지 않습니다.
- 최대 150개 단서를 표시합니다. 초과하면 잘림을 표시합니다. 일치한 소스 본문은 보고서에 포함하지 않습니다.
- 코드·결과를 DB에 저장하거나 외부 AI에 전송하지 않습니다. 화면을 새로고침하면 결과가 사라집니다. 다운로드한 보고서는 사용자가 관리합니다.

공개 GitHub API는 인증 없이 사용하며 자체 제공자 한도가 있습니다. 요청당 최대 15회 API 조회가 발생할 수 있습니다. 공유 서버에서는 다른 이용자의 조회도 한도에 영향을 줍니다. 한도 오류를 자동 반복하지 않으며 기다리거나 로컬 파일 검사를 사용할 수 있습니다. 추가 API 키는 필요하지 않습니다.

## 단서가 나왔을 때 보완 순서

1. 우선 설치·빌드·실행을 멈추고, 결과의 파일·줄 번호와 원본 커밋을 확인합니다. 문서·주석·정상 관리 코드일 수도 있으므로 경고만으로 파일을 삭제하지 않습니다.
2. 빌드 전 명령과 npm 설치 훅은 실행 내용·공식 제작자의 의도를 확인합니다. 불필요하거나 검증되지 않은 자동 실행은 제거하고, 필요한 정상 작업은 검토한 별도 명령으로 분리합니다. 가져오는 프로젝트·의존성도 따로 검토합니다.
3. 다운로드 즉시 실행·인코딩 PowerShell은 실행하지 않고 내용을 검토합니다. 공식 배포 출처와 해시·서명을 독립 대조한 뒤 격리 환경에서 판단합니다. 출처나 해시 일치 자체도 무해함을 보증하지 않습니다.
4. 보안 기능 비활성화·예외 추가·백업 삭제 지침은 따르지 않습니다. 이미 실행했다면 인터넷과 업무망에서 분리하고 보안 담당자에게 분석을 요청합니다. 무작정 예외를 삭제하거나 정책을 바꾸면 정상 환경에도 영향이 있으므로 확인 후 복구합니다.
5. GitHub Actions는 검토한 전체 40자리 커밋 SHA로 고정하고 최소 권한을 사용합니다. `pull_request_target`에서 외부 PR 코드를 받아 실행하는 흐름과 비밀정보 접근을 분리합니다. 수정 후 같은 자료를 재검사하고, 실제 기능·권한도 별도로 확인합니다.

감염·정보 탈취가 의심되면 아래 PC 확인과 계정 복구도 함께 진행합니다. 재검사에서 단서가 사라졌다는 사실만으로 감염이 제거되었다고 판단하지 않습니다.

## PC·GitHub 계정·Desktop 앱 확인

웹 페이지는 사용자의 PC 전체·브라우저 확장·설치 앱·GitHub 계정 권한을 임의로 읽을 수 없습니다. 저장소 HTTP 헤더가 정상이어도 내부 코드가 안전하다는 뜻은 아닙니다. 저장소의 별·다운로드 수·유효한 서명도 안전을 보증하지 않습니다.

Windows에서는 Windows 보안 → 바이러스 및 위협 방지 → 보호 업데이트를 확인하고 검사 옵션에서 전체 검사를 실행하세요. 오프라인 검사는 PC를 재시작하므로 작업을 저장한 뒤 직접 실행합니다. 프로젝트의 `scripts/check-github-campaign.ps1`은 공개된 일부 흔적·백신 상태·현재 연결·DNS 캐시만 읽고 JSON으로 출력합니다. 접근할 수 없는 항목은 `unavailable`로 남기며 보호 설정·파일을 변경하지 않습니다. 이 스크립트도 먼저 내용을 검토하세요.

GitHub 계정의 보안 로그·연결된 OAuth/GitHub Apps·토큰·SSH 키와 Desktop 앱의 공식 배포 출처·업데이트는 별도 수동 확인이 필요합니다. 의심 코드를 이미 실행했거나 감염 증거가 확인되면 기기를 격리하고 깨끗한 기기에서 세션·토큰 폐기와 계정 복구를 진행하세요.

## 검증과 한계

합성 텍스트를 사용해 위험·보완 예시, 입력 크기·경로·비밀 파일 제외, 중복 파일명, 결과 한도, GitHub 주소 제한, 커밋 고정, blob 변조, 심볼릭 링크 제외, 취소·제공자 한도·부분 검사를 검증합니다. 실제 악성 저장소를 내려받거나 실행하지 않습니다.

2026-11-09 검증: 전체 회귀 테스트 228개 통과, 타입 검사와 배포용 빌드·클라이언트 비밀 경계 검사 통과. 별도 임시 DB 환경에서 로그인·검사 선택·합성 파일 선택·읽기/전송 동의·설치 훅 단서 표시·입력 변경 시 결과/동의 초기화·공개 저장소 결과 표시를 확인했습니다. API는 비로그인 401, 다른 출처 403, 동의 누락 400, 정상 검사 200, 사용자 한도 429를 확인했습니다. 실제 악성 파일 실행·전체 PC 검사는 수행하지 않았습니다.

같은 날 Vercel 운영 배포 Ready, 운영 서버·DB 준비 상태 200, 비로그인 API 401, 다른 출처 403을 추가 확인했습니다. 운영 사이트에서 로그인된 일반 회원의 새 화면 진입·안내 펼치기·동의 후 실제 공개 저장소 검사와 결과 표시도 확인했습니다. 배포 환경변수·DB 구조 변경이나 새 API 키 추가는 필요하지 않습니다.

이 프로젝트를 검사하면 자체 읽기 전용 점검 스크립트에 포함된 공개 IP 지표가 단서로 표시될 수 있습니다. 확인한 항목은 현재 연결과 비교하기 위한 문자열이며 외부 접속·코드 실행 명령이 아닙니다. 경고의 파일·줄과 코드 맥락을 함께 확인해야 하는 사례입니다.

검증 중 문서가 파일 한도를 먼저 차지하는 현상을 발견해 문서·시험 자료보다 설치·빌드·소스 파일을 우선하도록 수정했습니다. 설치 폴더의 누락 의존성은 잠금 파일 그대로 설치 스크립트 실행 없이 복원했습니다. 합성 예시는 `tests/fixtures/repository/`에서 재현할 수 있습니다.

이 기능은 문자열 기반 초기 검토입니다. 난독화·다단계 다운로드·여러 파일의 실행 관계·모든 악성코드·신규 지표는 놓칠 수 있고 정상 관리 명령에도 단서를 표시할 수 있습니다. **단서 없음은 안전 판정이 아닙니다.**
