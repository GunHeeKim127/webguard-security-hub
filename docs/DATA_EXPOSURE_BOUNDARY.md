# 민감 식별자 노출 최소화

2026-10-27 로컬 변경. 화면 CSS/숨김 필드/더미 데이터 뒤에 원문을 넣지 않는다. 서버의 JSON·React 서버 컴포넌트(RSC) 응답 경계에서 허용 필드만 직렬화한다.

| 항목 | 브라우저로 보내는 것 | 서버 내부 |
|---|---|---|
| 현재 사용자 | 일부 가림 이메일·화면용 역할 | 인증 세션·실제 계정 ID·원문 이메일 |
| 관리자 IP 목록 | 전체 가림 주소·별도 management_id·위반 상태/시각 | 실제 IP·차단 행 |
| 관리자 계정 차단 목록 | 일부 가림 이메일·별도 management_id·위반 상태/시각 | 실제 user_id·원문 이메일·계정 차단 행 |
| 해제 요청 | action + blockId | 관리자 현재 권한 확인 → 참조를 실제 대상으로 조회 → 동일 참조 행인지 다시 확인하고 원자적 해제·감사 |
| 화면용 감사 이벤트 | 고정 종류·집계·시각 | 관리자 ID·대상 해시를 포함한 원래 감사 기록 |

관리 식별자는 개인정보를 대신하는 객체 참조이며 **비밀키/권한 증명은 아니다**. 유효 참조를 알아도 비로그인·일반 회원은 해제할 수 없다. 원문 IP/사용자 ID를 해제 API에 직접 보내는 기존 형태도 거절한다. 알 수 없는 이벤트 분류나 대상 해시를 UI에 그대로 전송하지 않고 안전한 종류로 정규화/집계한다.

PG migration **012** / 관리형 **008**이 IP·계정 차단 테이블에 고유 관리 식별자를 추가한다. 계정 정책의 PG 011 / 관리형 007 이후 적용해야 한다. 기존 적용 migration은 변경하지 않았다. readiness도 두 management_id 컬럼 유무를 확인한다. 운영 적용/배포는 아직 하지 않았다.

## 보호 범위와 필요한 실제 데이터

- 실제 원문을 DOM, aria 속성, data-* 속성, 숨겨진 입력, 초기 RSC prop 또는 JSON에 둔 채 마스크하지 않는다. 실제 값은 서버 권한 검사·DB 처리에서 사용한다. DB의 원문을 더미로 덮어쓰지 않는다.
- 로그인은 사용자가 입력한 실제 이메일/비밀번호를 승인된 서버에 HTTPS로 보내 인증해야 한다. 브라우저 소유자에게 그가 직접 입력한 요청값까지 숨긴다고 주장하지 않는다. 세션은 HttpOnly/SameSite 및 정식 HTTPS의 Secure 쿠키 정책을 유지한다.
- 비밀번호 해시·DB URL·서버 비밀키·서버 환경변수를 프로필 응답에 넣지 않는다. 이 변경은 DB 저장 암호화나 키 탈취 이후 보호를 새로 보증하는 기능이 아니다.
- 본인 진단의 대상·검사 결과·파일 SHA-256 등 기능 수행에 필요한 값은 소유자에게 정확히 제공한다. 실제 위험도/검사 결과를 더미 정상 값으로 바꾸지 않는다. 타 계정 결과 접근 제한은 기존 서버 조건을 유지한다.
- 사용자가 명시적으로 발급한 본인 자산용 수집 토큰은 외부 서버 연동에 필요한 일회 전달 값이다. 이를 서버 비밀키나 DB 자격과 혼동하지 않는다. 해당 기능의 발급 동작과 권한 검사를 유지한다.
- 전체 원문이 필요한 관리 조사는 승인된 DB 운영 경로에서 수행한다. 공개 클라이언트에 복호화 키를 넣거나 원문 조회 우회 API를 추가하지 않는다.

검증은 허용 필드 직렬화, 원문 이메일/IP/계정 ID/예시 비밀 해시 미포함, 이벤트 대상 해시 미노출, 관리 ID를 통한 실제 DB 해제 및 권한 거절, 초기 HTML/RSC 미노출을 대조한다. 운영 테이블/원문은 이번에 변경하지 않았다.
