# R02 — 관리형 DB 권한·비밀 유출·복구 경계

검토일: 2026-10-27. 운영 비밀값 조회·교체·DB 삭제를 수행하지 않은 코드 및 로컬 통합 검토입니다.

## 현재 확인한 경계

- 일반 PostgreSQL은 migration 소유 역할과 runtime 역할을 분리하고 runtime의 DB 소유·superuser·역할 생성 권한을 거절합니다. migration 후 부여 스크립트와 readiness로 확인합니다.
- Prisma Postgres 프로필은 제공자 관리 계정입니다. 앱에서 다른 이름을 지정해도 별도 SQL 역할이 생성되지는 않습니다. readiness의 `permissionModel=provider-managed`는 최소 권한 인증이 아닙니다.
- `lib/runtime-sql.ts`의 DDL·직접 사용자 변경·아카이브 접근 등 차단 검사와 매개변수화된 쿼리는 앱 내부 오용을 줄입니다. 완전한 SQL 허용 목록이나 DB 권한 경계는 아닙니다. **유출된 DB URL/제공자 키로 외부에서 직접 연결하는 행위까지 막지 못합니다.** 사용자별 데이터 분리는 서버 쿼리의 소유자 조건이며 제공자 역할/RLS 격리 보증이 아닙니다.
- DB URL·API 키는 서버 환경변수만 사용합니다. 공개 `NEXT_PUBLIC_*`, 화면, Git, 보고서, 스크린샷에 복사하지 않습니다. 풀링 runtime URL과 직접 migration URL의 용도도 구분합니다.
- 기존 통합 테스트는 runtime DDL/다른 사용자 데이터 접근/비밀번호 해시/세션 취소/데이터 보관·이전·트랜잭션 실패 경계를 검증합니다. 제공자 콘솔의 키별 실제 권한 및 백업 보존 기간은 이 테스트로 증명할 수 없습니다.

## 운영자가 확인할 사항

1. 제공자 콘솔에서 해당 프로젝트 전용 리소스와 연결 자격의 권한을 확인합니다. 다른 프로젝트 공용 자격을 쓰지 않습니다. 제공자가 지원하는 실제 읽기/쓰기/관리 권한 분리를 확인하고 지원되지 않으면 잔여 위험으로 기록합니다.
2. Vercel Production/Preview/Development의 자격 범위를 구분합니다. Preview가 운영 데이터에 연결되지 않는지 확인합니다. 값은 문서나 채팅으로 보내지 않습니다.
3. 백업 보존 기간·시점 복구 지원·복구 담당자를 기록하고 별도 테스트 DB에서 복구 후 행 수·소유자·스키마 버전·읽기/쓰기 권한을 대조합니다. 제공자 복구 훈련은 아직 미실시입니다.

## 유출이 의심되면

1. 사고 시각·노출 경로·배포 ID를 기록하고 로그인/진단 노출을 일시 제한합니다. 보호 DB 장애 시 검사를 우회해 허용하지 않습니다. 로그에 원문 키를 붙이지 않습니다.
2. 제공자에서 새 프로젝트 전용 자격을 발급하고 운영 환경변수를 교체해 재배포합니다. 준비 상태·로그인·소유자 격리를 확인한 뒤 **기존 키를 폐기**합니다. 새 키 발급만으로 기존 키는 무효화되지 않습니다. 폐기 후 기존 키 연결이 실패하는지도 운영자가 확인합니다.
3. 노출 범위에 따라 세션·집계 수집 키·LLM 키 등 관련 자격을 취소합니다. 사용자 암호 해시가 유출된 경우 영향 평가와 사용자 안내/비밀번호 재설정 절차가 필요합니다. 단순 DB 비밀번호 변경이 이미 발급된 앱 세션을 취소하지는 않습니다.
4. 제공자 접속 기록·Vercel 요청/실행 로그·변경 이력을 대조하고 승인되지 않은 쓰기 여부를 확인합니다. 손상이 확인된 경우 별도 DB로 복구·검증한 뒤 전환합니다. 정상 원본과 증거를 먼저 보존하고 운영 DB를 덮어쓰지 않습니다.
5. 파일/Git에서 지운 것으로 끝내지 않습니다. 자격 폐기와 과거 이력/CI/로그 노출 범위를 확인하고 복구 시각·담당자·검증 결과를 기록합니다.

## 이번 판단

앱 내부 제한과 자체 PostgreSQL 역할 분리의 회귀 검증은 가능하지만 관리형 자격 유출의 영향 범위가 제거된 것은 아닙니다. **R02는 잔여 위험 있음**으로 유지합니다. 실제 제공자 최소 권한 확인·백업 복구 훈련·키 폐기 실증 전에는 해결 완료로 표시하지 않습니다.
