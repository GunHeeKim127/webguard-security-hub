# 다른 컴퓨터의 Linux·네트워크 실환경 검증 계획

작성일: 2026-10-22. 아래 절차·사례표는 **실환경 검증 계획이며 전체 완료 기록이 아니다.** 프로젝트 상태는 1단계 완료·2단계 진행 중이다. 이후 현재 PC에서 수행한 합성·회귀 검사와 VM 접근 확인은 [별도 실행 기록](LOCAL_ENVIRONMENT_VALIDATION.md)에 구분했다. 로컬 SQL은 미설정이며 Kali는 SSH/root라는 사용자 설명을 확인했으나 현재 실행 환경의 키 인증은 거절됐다. 실제 SSH 설정·유효 정책 대조는 아직 미검증이다.

## 1. 환경과 검증 상태

| 대상 | 사용자 환경·계획 | 서비스 상태 | 별도로 확인할 것 |
|---|---|---|---|
| Linux | 보유 환경을 다른 컴퓨터에서 확인 예정 | SSH 설정 파일 분석 구현 | 실제 설정과 판정 대조·다른 기기의 사용 흐름 |
| macOS | 실제 Mac에서 확인하기 어려움 | Mach-O 구조·로컬 도구 경로 구현 | 실제 OS 서명 조회는 미검증·보류 |
| Network | 다른 컴퓨터에서 실습·검증 예정 | 버튼 준비 중·진단 엔진 미구현 | 환경·제조사·버전·설정 형식 확정, 향후 구현 검증 |

개발 PC의 자동 테스트 통과, 다른 기기에서 사이트 접속, 실제 장비 상태의 정확한 진단은 서로 다른 확인이다. 실물/VM/시뮬레이터의 결과도 구분한다.

## 2. 공통 준비와 다른 기기 이용

1. 정식 https://webguard-security-hub.vercel.app/ 에 같은 계정으로 로그인한다. 실행은 admin/analyst이며 신규 viewer는 조회 전용이다.
2. 다른 컴퓨터의 OS·브라우저·네트워크 구분과 검사 대상 정보를 기록한다. 실제 값을 확인하기 전에는 버전을 추측하지 않는다.
3. 허가된 파일/설정의 검토용 복사본과 예상 결과를 준비한다. 프로젝트 전체·DB 비밀번호·API 키를 다른 컴퓨터에 복사할 필요는 없다.
4. 진단 후 같은 계정의 첫 컴퓨터에서도 결과가 보이고 새로고침 후 유지되는지 확인한다. 허가된 별도 테스트 계정에서는 그 기록이 보이지 않아야 한다.
5. 한 기기의 로그아웃과 다른 기기의 독립 세션을 확인한다. 기기 변경을 이유로 역할을 높이거나 보호를 끄지 않는다.

실패 시 주소·시각·문구/오류 코드·역할·검사 종류를 기록한다. 비밀번호·쿠키·토큰·개인키는 기록하지 않는다. 로그인, 권한, 사이트 접속 보호, 입력 형식, 실습 장비 접근 문제를 구분한다.

## 3. Linux 현재 기능의 실검증

### 현재 지원 범위

- 진입: 검사 선택 → Endpoint → Windows·macOS 실행 파일 및 시스템 진단 작전실 → Linux SSH 설정.
- 검사 ID: `linux.ssh`. 현재 모듈 버전은 `1.0.0`, 규칙 버전은 `2026-10-19.1`이며 실제 실행 결과의 두 필드를 각각 기록한다.
- 입력: 최대 64 KiB `sshd_config` 텍스트. 원격 SSH 접속·자동 수집이 아니다.
- 대상: 명시적 전역 PermitRootLogin, PasswordAuthentication, PermitEmptyPasswords, PubkeyAuthentication, MaxAuthTries.
- Linux ELF·패키지 CVE·계정 권한·서비스·방화벽 전체 진단은 현재 미지원이다.
- 브라우저에서 이 검사를 이용하는 데 Node.js나 Windows/macOS 실행 파일용 로컬 도구는 필요하지 않다.

### 수행 순서

1. 배포판·버전·OpenSSH 버전·실물/VM·설정 수집 시각을 기록한다. 모르는 값은 미확인으로 둔다.
2. 운영자가 읽기를 허가한 설정의 검토용 복사본을 준비한다. 민감한 경로·사용자명·주소의 공유 범위를 확인한다. Include/Match를 제거해 실제 유효 설정인 것처럼 만들지 않는다.
3. 아래 합성 사례를 먼저 확인하고 실제 복사본을 별도 자산 이름으로 진단한다.
4. 근거의 줄 번호와 판정이 입력과 맞는지, 실제 유효 설정과 어떤 차이가 있는지 운영자가 대조한다.
5. 개선된 검토용 복사본을 같은 이름·같은 검사 종류로 재검사해 이력과 개선 비교를 확인한다.
6. 결과 JSON·캡처·기대/실제 차이를 기록한다. 실제 SSH 서비스 설정 변경·재시작은 이 절차에 포함하지 않는다.

### 테스트 사례 — 아직 미실행

다섯 설정의 순서는 PermitRootLogin / PasswordAuthentication / PermitEmptyPasswords / PubkeyAuthentication / MaxAuthTries다.

| 사례 | 입력 | 현재 엔진에서 기대할 결과 |
|---|---|---|
| 검토 필요 합성 사례 | yes / yes / yes / no / 8을 명시 | 경고 5개 |
| 개선 복사본 | no / no / no / yes / 4를 명시 | 기본 통과 5개; 위 사례 대비 개선 관찰 5개 |
| 일부 값 누락 | 다섯 설정 중 일부만 제공 | 누락 항목 미검사; 기본값을 추정하지 않음 |
| Include/Match | 해당 지시문 포함 | 현재 모듈은 유효 정책을 확정하지 않아 다섯 규칙을 미검사 처리 |
| 복잡한 구문 | 인용부호·역슬래시 등 포함 | 현재 파서 제한에 따라 유효 정책 판단 보류 |
| 관련 없는 내용/크기 초과 | 관련 지시문이 없는 파일 또는 64 KiB 초과 | 입력 거절·실패 안내, 기존 성공 기록 보존 |
| 같은 자산 재검증 | 같은 계정·이름·검사 종류 | 새 실행 추가·이전 실행 보존·비교 가능 |
| 기기·계정 분리 | 다른 기기의 같은 계정 / 별도 계정 | 같은 계정 결과 공유 / 타 계정 기록 비공개 |

합성 데이터는 파서와 판정의 검증용이며 위험한 값을 실제 SSH 서비스에 적용하는 지침이 아니다. 개별 설정의 통과가 서버 전체 안전을 뜻하지 않는다. 사설 IP를 기존 웹 URL 칸에 넣거나 SSRF 방어를 완화하지 않는다.

### 완료 근거

실제 OS/버전·설정 출처/시점, 입력과 판정의 일치, 미검사 표시, 개선 비교·이력, 같은 계정의 다른 기기 조회를 기록한다. 차이가 있으면 비밀정보 없는 최소 재현 사례로 수정·재검증한다. 전체 OS·키·포트·패키지 등 확인하지 않은 영역은 미검사로 남긴다.

## 4. 네트워크 — 구현 전 준비와 구현 후 검증

**현재 사이트의 Network 버튼으로 장비 검사를 실행할 수 없다.** 아래는 준비·향후 개발 검증 계획이다.

### 먼저 확인할 환경

- 실장비/시뮬레이터/VM 구분, 제조사·모델·OS/펌웨어 버전.
- 다른 컴퓨터의 실습 구성, 운영 장비인지 여부, 진단 허가 범위.
- 제공 가능한 설정 내보내기 형식과 민감정보 제거 방법.
- 단일 장비인지 라우터·스위치·방화벽 여러 종류인지.
- 설정 파일 분석만 필요한지 향후 읽기 전용 연결까지 필요한지.

Cisco나 특정 시뮬레이터를 쓴다고 가정하지 않는다. 화면 캡처만으로 전체 설정이나 실제 적용 상태를 확정하지 않는다.

### 개발·검증 순서

1. 대상 버전의 공식 기준을 확인해 지원할 항목을 정한다. 후보는 관리 접속·SSH/Telnet·SNMP·관리 접근 제한·로깅 등이다. 아직 구현된 규칙은 아니다.
2. 원문을 저장하거나 실행하지 않는 설정 복사본 분석 파서를 우선 구현한다.
3. 정상·검토 필요·누락·미지원 버전·손상/초과 입력을 구분한다. 누락을 무조건 안전 또는 취약으로 단정하지 않는다.
4. 공통 근거·개선안·위험도·규칙 버전·미검사 표시와 계정별 저장·재검증을 확인한다.
5. 준비된 다른 컴퓨터의 실습 환경에서 설정과 결과를 대조한다. 시뮬레이터와 실장비 결과를 구분한다.
6. 확인한 지원 범위에 한해 Network 작전실을 활성화한다.

SSH/SNMP/API 접근·에이전트·자동 수집·설정 변경은 별도 설계가 필요한 향후 기능이다. 기존 웹 검사의 SSRF 방어를 해제하거나 장비/DB 포트를 인터넷에 공개하는 방법을 전제로 삼지 않는다. 네트워크 미구현 상태를 2단계 완료로 표시하지 않는다.

## 5. macOS 보류 기록

- 구현·기존 검사: Mach-O/Universal 구조·경계·요약의 합성 테스트 이력이 있다.
- 미검증: 실제 Mac OS에서 codesign/spctl과 로컬 도구를 함께 사용한 종단 동작.
- 사유: 사용자가 실제 Mac에서 확인하기 어려운 상황. 보유 장비를 추측하지 않는다.
- 현재 가능한 확인: 허가된 샘플의 제한된 구조·손상 거절·동의·취소·요약 처리.
- Mac 확보 후: OS·아키텍처·도구 버전·정상/손상 파일·서명 조회·실패/판정 불명 처리 확인.
- 구현 완료·합성 검증·실환경 미검증을 분리한다. 실행·공증·악성코드 없음까지 통과했다고 표시하지 않는다.

## 6. 검증 결과 기록 양식

아래 한 묶음을 사례마다 복사한다. 현재 결과는 모두 미실행이다.

| 항목 | 기록 |
|---|---|
| 일시·수행자 | 미기입 |
| 사이트·배포/커밋 | 미기입 |
| 접속 컴퓨터·OS·브라우저 | 비밀정보 없는 구분명으로 기입 |
| 대상 OS/장비·버전·실물/VM/시뮬레이터 | 미기입 |
| 계정 역할 | 이메일·비밀번호 대신 역할만 기입 |
| 작전실·검사 ID·규칙 버전 | 미기입 |
| 설정 출처·수집 시점·진단 허가 | 원문·자격증명 없이 기록 |
| 입력 사례·예상 결과 | 미기입 |
| 실제 결과·JSON/캡처 위치 | 미실행 |
| 판정 | 미실행 / 통과 / 실패 / 미검증 / 보류 |
| 차이·원인·수정·재검증 | 미기입 |
| 남은 제한 | 미기입 |

예시를 실제 결과로 채우거나 계획만으로 완료 체크하지 않는다. 권한 거절·입력 거절·미검사는 각각 기대 동작과 비교해 판정한다. 자료에 비밀값을 넣지 않고 기존 계정·DB·결과를 초기화하지 않는다.
