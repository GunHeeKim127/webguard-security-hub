# Mac 담당자 전달용 — Endpoint 실제 파일 검증

아래 안내를 그대로 전달하면 됩니다. 새 PKG/DMG 기능의 실제 Mac 동작을 확인하기 위한 절차입니다. 기존 .app/Mach-O의 JSON 생성·사이트 저장/조회는 사용자 보고로 확인했으며, 이번에는 최신 도구로 형식별 결과를 구분해 확인합니다.

## 1. 준비

- 본인 소유이거나 검사 허가를 받은 Mac과 파일을 사용합니다.
- 설치된 Node.js 20 이상이 필요합니다. 터미널에서 `node --version`으로 확인합니다. 없다면 준비되지 않았다고 알려 주세요. 검사하려는 앱·PKG·DMG를 설치하거나 실행할 필요는 없습니다.
- 가능하면 `.app`, `.pkg`, `.dmg`를 각각 하나씩 준비합니다. 세 파일을 한 번에 선택하지 않고 **각각 따로 검사**합니다. 없는 종류는 “보유 파일 없음”으로 알려 주세요.
- `.pkg`는 XAR 기반 플랫 설치 패키지, `.dmg`는 UDIF 이미지가 현재 대상입니다. 오래된 폴더형 PKG, 암호화·특수 이미지, 스크립트 기반 앱 등 모든 변형을 지원하는 것은 아닙니다.
- 관리자 비밀번호, `sudo`, 보안 기능 해제, 전체 디스크 권한 부여는 이 절차에 필요하지 않습니다. 접근할 수 없는 파일은 억지로 권한을 바꾸지 말고 상태를 알려 주세요.

## 2. 두 도구를 새로 다운로드

예전 파일이 남아 있어도 아래 **두 파일을 모두 새로** 받습니다.

1. [검사 도구 executable-inspector.mjs](https://webguard-security-hub.vercel.app/tools/executable-inspector.mjs)
2. [Mac 실행 안내 mac-inspector.command](https://webguard-security-hub.vercel.app/tools/mac-inspector.command)

또는 [Endpoint](https://webguard-security-hub.vercel.app/workbench/endpoint) 상단의 두 다운로드 버튼을 사용합니다. Mac 파일 검사 자체는 로컬 도구에서 하고, 사이트에는 생성된 JSON 요약을 가져옵니다.

두 파일을 같은 폴더에 두면 편합니다. 실제 폴더가 Downloads·Desktop·다른 위치인지 가정하지 않습니다. 서로 다른 폴더여도 실행 안내에서 실제 검사 도구를 선택할 수 있습니다. 다운로드 중복 번호가 붙었어도 실제 받은 파일을 사용합니다.

이번 전달 기준 도구 버전은 **2026-10-29.4**입니다. 확인하려면 터미널에 `node `를 입력하고 실제 `.mjs`를 끌어놓은 다음 공백과 `--version`을 붙여 실행합니다. `VELTHARA executable inspector 2026-10-29.4`이 나와야 합니다.

## 3. 실행 안내 시작

1. 터미널에 아래 내용과 **끝의 공백**을 입력합니다.

   ```text
   /bin/zsh
   ```

2. Finder에서 **실제로 내려받은** `mac-inspector.command`를 터미널에 끌어놓습니다.
3. Enter를 누릅니다. 파일의 실제 경로는 드래그로 입력합니다. 예시 사용자명·예시 앱 경로를 복사하지 않습니다.
4. 검사 도구를 찾지 못하면 새로 받은 `.mjs`를 선택합니다. Node 위치를 물으면 설치된 Node.js 실행 파일을 선택합니다. Node가 없으면 취소하고 알려 주세요.

## 4. 검사할 파일 선택

1. 첫 창에서 **Choose one app, installer, image or executable**을 선택합니다.
2. 실제 `.app`, `.pkg`, `.dmg` 중 하나를 선택합니다. `.app`은 앱 묶음 자체를 선택하면 됩니다. Applications 밖의 파일도 허용 범위에서 선택할 수 있습니다.
3. 위치를 모르면 **Search a folder for candidates**로 본인이 지정한 폴더의 후보를 찾을 수 있습니다. 검색에는 깊이·개수 제한이 있고 링크·접근 불가 위치를 생략할 수 있습니다. 후보가 없다고 파일이 존재하지 않는다는 뜻은 아닙니다.
4. 읽기 허용 창에서 선택을 확인합니다.
   - **Static only**: 구조·목록 등만 확인합니다. 서명이 unknown이어도 이 모드에서는 정상적인 미검사 상태일 수 있습니다.
   - **Native checks**: 위 검사와 함께 Mac 서명·Gatekeeper를 조회합니다. **이번 서명 검증에는 이 항목을 선택**해 주세요. OS 신뢰 서비스에 네트워크 조회가 발생할 수 있습니다.
   - **Cancel**: 취소합니다. 취소 자체는 보안 오류가 아닙니다.
5. 결과 JSON을 저장할 **존재하는 폴더와 새로운 이름**을 선택합니다. 종류별로 다른 이름을 쓰고 기존 파일을 덮어쓰지 않습니다.

앱 실행·PKG 설치·DMG 마운트·내부 파일 압축 해제는 하지 않습니다. 검사 중에는 대상 파일을 이동하거나 교체하지 않습니다.

## 5. 결과 확인 — 정상 완료와 안전 판정은 다릅니다

JSON이 생성되고 터미널에 `Read-only inspection complete`가 나오면 도구 실행이 끝난 것입니다. 서명 거절·미서명·미검사 항목이 있다고 도구 실행 자체가 실패한 것은 아닙니다.

| 선택한 대상 | 이번에 확인하는 것 | 확인하지 않는 것 |
| --- | --- | --- |
| `.app` / Mach-O | 주 실행 파일 구조·보호 선언·SHA-256, Native 동의 시 Mac 서명·Gatekeeper·일부 선언 | 앱 전체 파일·모든 보조 프로그램·악성코드 여부·실행 동작 |
| `.pkg` | 컨테이너 목록·설치 파일 목록 조회·Scripts 영역 존재, Native 동의 시 서명·설치 정책 조회·파일 SHA-256 | 설치 스크립트 본문 분석·실제 최종 설치 위치·내부 실행 파일 코드 |
| `.dmg` | 이미지 메타데이터·가능한 체크섬 검증, Native 동의 시 서명·열기 정책 조회·파일 SHA-256 | 마운트·내부 앱/패키지의 코드·실제 실행 |

기술값을 확인할 경우:

- `.app` 해시는 **주 실행 파일 기준**입니다. PKG/DMG는 선택한 컨테이너 파일 전체를 해시합니다.
- PKG/DMG 결과는 Mac 모듈의 공통 요약 형식을 사용합니다. 상위 `format`이 `macho`여도 실제 컨테이너 종류는 `container.kind`의 `pkg` / `dmg`로 구분합니다.
- `payloadListed=false`이면 설치 파일 목록 조회를 못한 것입니다. `payloadEntries=0`만 보고 내용이 없다고 판단하지 않습니다.
- `scriptsPresent=true`는 스크립트 영역이 관찰됐다는 뜻이며 그 자체로 취약점이 아닙니다.
- `unknown`은 **확인하지 못함**, `unsigned`는 **미서명**, `rejected`는 **해당 OS 정책이 허용하지 않음**입니다. 서로 다른 상태입니다.
- 유효한 서명·체크섬·정책 허용도 악성코드가 없다는 보증은 아닙니다. 도구가 원본 파일을 서버에서 독립 검증하는 것도 아닙니다.
- 도구2026-10-29.4는 OS 조회 전후 파일 전체를 SHA-256으로 두 번 읽고 식별자·크기·수정 시각도 대조합니다. 메타데이터 변경 시각만 달라지고 내용 해시가 일치하면 그 사실을 요약의 `stability`에 기록합니다. 실제 바이트·파일 교체·크기/수정 시각 변경은 계속 차단합니다. 큰 파일은 두 번 읽기 때문에 시간이 더 걸릴 수 있습니다.

## 6. 일반 회원으로 사이트 저장·재조회

1. [Endpoint](https://webguard-security-hub.vercel.app/workbench/endpoint)에 일반 회원으로 로그인합니다. 비밀번호·인증 코드는 전달하지 않습니다.
2. 점검할 항목에서 **macOS 실행 파일 · 기기 내 점검**을 선택합니다.
3. **검사할 Mac 파일 종류**에서 실제 검사한 종류를 선택합니다. APP/PKG/DMG를 선택하면 로컬 도구 안내와 JSON 가져오기로 전환됩니다.
4. 자산 이름을 입력합니다. 전체 경로·계정·비밀값은 이름에 넣지 않습니다. 종류별로 구분되는 간단한 이름이면 됩니다.
5. **결과 JSON 선택**에서 방금 만든 JSON **하나만** 선택합니다. 여기에 앱·PKG·DMG 원본을 넣지 않습니다.
6. 현재 파일 읽기를 허용하고 **허용한 파일 점검**을 누릅니다. 요약 형식과 미검사 안내를 확인합니다.
7. 점검 권한·분석 동의를 확인한 뒤 **요약 전송·결과 저장**을 누릅니다. 이때 요약이 사이트로 전송됩니다. 원본은 전송하지 않습니다.
8. **내 결과**로 이동해서 방금 저장한 기록과 상세 내용을 다시 엽니다. **결과 JSON 다운로드**도 확인합니다.
9. 나머지 보유 형식도 한 종류씩 반복합니다. 파일이 없거나 확인 불가이면 해당 상태 그대로 기록합니다. 테스트용 가짜 결과를 사이트에 저장하지 않습니다.

## 7. 오류가 생기면

같은 명령을 계속 반복하거나 보안 설정을 해제하지 말고 아래처럼 구분해서 알려 주세요.

| 표시 | 확인할 것 |
| --- | --- |
| `MODULE_NOT_FOUND` | 대상 앱 이전에 검사 도구를 못 찾은 상태입니다. 실제 받은 `.mjs` 위치를 선택했는지 확인합니다. |
| `TOOL_OUTDATED` / `TOOL_NOT_FOUND` | 도구 두 개를 함께 다시 받고 실제 파일을 선택합니다. |
| `NODE_NOT_FOUND` / `NODE_VERSION_UNSUPPORTED` | 설치된 Node와 `node --version` 결과를 확인합니다. |
| `TARGET_NOT_FOUND` / `ACCESS_DENIED` | 파일이 실제로 있는지, 본인에게 읽기 권한이 있는지 확인합니다. 경로 이름 자체가 취약점이라는 뜻은 아닙니다. |
| `APP_METADATA_READ_FAILED` / `APP_EXECUTABLE_NOT_FOUND` | 앱 정보나 주 실행 파일을 확인하지 못한 상태입니다. 이름이 .app이라는 이유로 정상 구조를 가정하지 않습니다. |
| `MAIN_EXECUTABLE_IS_SCRIPT` | 정상 앱일 수도 있지만 주 실행기가 Python/셸 등이라 현재 Mach-O 구조 검사 밖입니다. |
| `CONTAINER_FORMAT_UNSUPPORTED` | 확장자와 지원하는 실제 PKG/DMG 형식이 일치하지 않거나 특수/구형 형식일 수 있습니다. 손상·악성 확정이 아닙니다. |
| `CONTAINER_READ_FAILED` / `CONTAINER_LIMIT` | OS 도구 조회 실패·해석 한도 등으로 확인하지 못했습니다. 가능한 원인을 확정하지 말고 진단 코드를 전달합니다. |
| `FILE_CHANGED_DURING_INSPECTION` | 검사 전후 상태가 일치하지 않아 결과를 확정하지 못했습니다. 새 버전의 Diagnostic으로 변화 종류를 확인하고 업데이트/이동이 끝난 파일을 다시 선택합니다. |
| `OUTPUT_EXISTS` / `OUTPUT_FOLDER_NOT_FOUND` | 기존 파일과 겹치지 않는 새 JSON 이름·실제로 있는 저장 폴더를 선택합니다. |
| 사이트의 “확인 불가 결과 파일” | 최신 도구의 JSON인지, 다른 모듈이나 원본 파일을 선택한 것은 아닌지 확인합니다. |

오류 시 도구가 출력한 **`Diagnostic: {...}` 한 줄**을 전달합니다. Terminal 전체 화면·전체 경로·파일 원본은 필요하지 않습니다. 해당 줄에도 개인정보가 없는지 확인해 주세요. `Diagnostic`이 없으면 오류 코드만 전달합니다.

이전2026-10-29.3의 DMG stability 오류는 구체적으로 어떤 속성이 달라졌는지 기록하지 않아 파일 변조로 확정할 수 없습니다. 새 버전에서 같은 오류가 나면 Diagnostic의 `stability`에 파일 교체·크기·수정 시각·메타데이터·내용 해시 변화 여부가 **참/거짓으로만** 추가됩니다. inode/장치 번호·시각 원값·경로는 전달하지 않습니다. 기존 오류를 재검증할 때는 도구 두 파일을 함께 다시 받아야 합니다.

## 8. 담당자가 회신할 내용 — 복사해서 사용

```text
Mac 검증 회신
- macOS 버전:
- Apple Silicon / Intel:
- Node 버전:
- 검사 도구 버전:
- 계정 권한: 일반 회원 / 기타

.app: 미보유 / 확인 불가 / JSON 생성 완료
.pkg: 미보유 / 확인 불가 / JSON 생성 완료
.dmg: 미보유 / 확인 불가 / JSON 생성 완료

각 형식의 Native checks 선택 여부:
각 형식의 사이트 JSON 가져오기:
각 형식의 저장 후 내 결과 재조회:
각 형식의 결과 JSON 다운로드:

문제가 있었던 단계:
오류 코드 또는 Diagnostic 한 줄:
정상 생성된 결과 JSON 첨부 가능 여부:
```

macOS 버전은 “이 Mac에 관하여”에서, CPU 종류는 칩/프로세서 표시에서 확인합니다. 기기 일련번호·사용자명·이메일·비밀번호·개인키는 회신하지 않습니다. 정상 JSON을 전달하면 구조·서명 주장·미검사 구분·사이트 기록을 다시 대조할 수 있습니다. 파일이 없거나 실행하지 못한 종류는 완료로 계산하지 않습니다.
