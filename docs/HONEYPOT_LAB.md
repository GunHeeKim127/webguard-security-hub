# 분리된 허니팟 실습 검증

현재 도구는 소유한 Linux 실습 VM 안에서 잠깐 실행하는 저상호작용 디코이와 격리 시험입니다. 운영 고객 요청을 전달하거나 공개 서비스로 배치하는 기능은 아닙니다. 기존 사이트의 단순 디코이 응답과 별도입니다.

## 준비와 실행

Linux VM의 Python 3, `unshare`, `ip`와 root 권한이 필요합니다. 패키지는 자동 설치하지 않습니다. VM에서 [격리 검증 도구](https://webguard-security-hub.vercel.app/tools/honeypot-isolation-check.py)를 다운로드하고 다음과 같이 실행합니다. 다운로드는 아래 해시와 일치해야 합니다.

```sh
sha256sum honeypot-isolation-check.py
sudo python3 -I -S honeypot-isolation-check.py
```

도구 SHA-256: `91b0b3e198284675d95748b064e624947949ef4a3afde4eabfdbdc5bc1a87f5a`

## 확인하는 것

- 새 네트워크 namespace에서 loopback 인터페이스만 사용하며 샘플 공개/사설 주소로의 연결이 경로 없음으로 거절되는지 확인합니다.
- 디코이 프로세스를 빈 파일시스템으로 격리하고 일반 사용자 권한으로 낮춥니다. 코어 덤프·파일 쓰기·CPU·메모리·파일 개수에 한도를 둡니다.
- 5개 로컬 요청의 고정 응답·쓰기 거절과 집계만 확인합니다. 원본 요청 주소·IP·본문은 기록하지 않으며 파일·쉘·DB를 실행하지 않습니다.
- 자체 프로세스·임시 디렉터리를 정리합니다. 기존 방화벽·서비스·VM 네트워크 설정을 수정하지 않습니다.

성공 JSON의 `cleanup`이 `complete`여야 합니다. 오류가 나오면 그 코드를 근거로 미검증 상태를 유지합니다. 커널 namespace 지원·권한·보안 정책에 따라 실행이 거절될 수 있습니다. 환경 제한을 우회하거나 운영 보호를 끄지 마세요.

## 현재 검증 상태

도구 구현·검토 완료, 실제 Linux VM 실행 결과 대기입니다. Windows에서 성공한 것으로 기록하지 않습니다. 지속 운영·외부 유입·호스트 공격·모든 탈출 기법·커널 안전성을 검증한 것은 아닙니다. 운영 트래픽 연결과 장기 실행은 별도 설계·검증 후 진행합니다.
