## A. 먼저 환경을 구분

1. PC OS·브라우저·Node와 Android Studio/APK Analyzer/Android SDK 등 **실제로 설치된 분석 도구**를 확인합니다. 있으면 그 버전과 공식 사용법으로 진행하고, 없으면 필요한 도구를 설명해 사용자에게 준비를 요청합니다. 무관한 도구를 대량 설치하지 않습니다.
2. USB/에뮬레이터 없이도 실제 APK의 정적 대조는 가능합니다. 연결된 실기기가 있으면 Android 버전·브라우저에서의 실제 파일 선택/검사를 별도 확인합니다. ADB/개발자 설정을 정적 검사 때문에 강제로 켜지 않습니다.
3. 본인 또는 허가받은 **실제 APK 하나**를 준비합니다. 원본 파일명·경로·개인정보는 검증 문서에 남기지 않습니다. 악성 앱 설치/실행을 요구하지 않습니다.
4. 기존 Android Chrome 확인은 “파일 미선택 오류/동일 계정 PC 기록 조회”까지만 완료입니다. 실제 APK 해독/독립 도구 대조가 끝났다고 가정하지 않습니다.

## B. 현재 지원 범위를 정확히 대조

| 형식 | 사이트가 보는 것 | 별도 검증/미지원 |
| --- | --- | --- |
| APK | ZIP 구조·제한된 AXML의 명시적 debuggable/allowBackup/usesCleartextTraffic·권한 선언 수 | 기본값/리소스 참조 전체·네트워크 예외·exported·서명 신뢰·DEX/악성코드·실제 승인/실행 |
| AAB | 목록·base Manifest 위치 등 구조 | protobuf Manifest 해독·배포 APK 생성/내용·서명 |
| APKS/XAPK | 컨테이너 구조·중첩 APK 목록 | 내부 APK 전체 분석/설치·서명 |

독립 도구가 기본값을 표시해도 사이트가 명시값 없는 항목을unknown/미검사로 표시하는 것은 오류가 아닙니다. 사용자가 제공한 실제 명시값·리소스 참조·기본값을 구분하세요. allowBackup/cleartext 등의 선언을 발견했다고 실제 통신이나 침해를 확정하지 마세요.

주요 제한은 파일8GiB 이하, 범위 읽기8MiB/중앙 목록4MiB·50,000항목, 개별 설정1MiB·압축 비율/해제 상한, Worker20초입니다. ZIP64·분할·암호화 ZIP은 미지원입니다. 크기가 작아도 특수 구조이면 확인 불가일 수 있습니다. 오래된 APK 서버 모드는2MiB이며 새 모바일 패키지 모드와 다릅니다.

## C. 실제 APK로 파서·플랫폼 출력 교차 대조

1. 독립 플랫폼 도구로 실제 Manifest의 세 Boolean 명시값·지원하는 uses-permission 선언 수를 읽고 사이트 관찰값과 비교합니다. 새 도구 명령/출력은 설치된 버전의 공식 문서를 확인합니다.
2. 사이트의 parsed/decode 상태가false이면 원문 확인 없이 값을 채우지 않습니다. 리소스 참조·지원하지 않는 AXML·압축 한도 등 확인한 이유만 기록합니다.
3. APK 서명을 독립적으로 확인할 수 있어도 사이트가 서명 신뢰를 미검사로 표시하는 것은 현재 범위상 정상입니다. 서명 검증을 사이트 기능 완료로 합산하지 않습니다.
4. 실제 파일 무결성, ZIP CRC, 설치 가능성, 런타임 안전성, 모든 권한/모든 취약점은 위 정적 관찰로 증명되지 않습니다.
5. AAB/APKS/XAPK를 보유했다면 실제 구조 분류만 별도 대조합니다. 없는 형식은 “파일/환경 없음”으로 남깁니다.

## D. 브라우저·일반 회원 흐름

주소: https://webguard-security-hub.vercel.app/workbench/mobile

1. 일반 회원으로 로그인하고 실제 APK는 **모바일 APK·AAB·IPA·APKS·XAPK** 모듈에서 검사합니다. 다른 고객 데이터를 보지 못하는지 전용 허가 시험 계정 범위에서 확인합니다.
2. 파일 미선택→선택 오류, 파일 선택만 함→내용 미읽음, 읽기 미동의→검사 차단을 확인합니다. 최대 파일1개를 유지합니다.
3. 현재 파일 읽기 허용→기기 내 검사→전송 요약 확인→별도 소유/점검 동의→저장→내 결과 조회→JSON 다운로드를 실제로 수행합니다.
4. 파일/모드/모듈 변경·취소·로그아웃 때 이전 동의/요약이 재사용되지 않는지 확인합니다. 기존 기록을 현재 미완료 검사의 새 결과로 오해하지 않게 구분합니다.
5. 같은 실제 자산 재검증과 PC/Android Chrome 동일 계정 기록 조회를 확인합니다. 미검사→미검사를 개선으로 표시하면 안 됩니다.
6. 기본 브라우저 방식은 원본 미전송이며 전체 해시를 계산하지 않는 자기 보고 요약입니다. 서버 원본 검증은 별도 전송 동의·2MiB 상한을 확인하고 사용자가 허가한 경우에만 사용합니다.
7. 테스트/손상/빈 파일·합성 취약/보완 쌍은 **격리 로컬에서만** 검증합니다. 운영에 자동 샘플·더미 파일·가짜 진단 결과를 저장하지 않습니다. 사용자 선택 파일 대신 샘플을 검사하지 않습니다.

## E. 오류 수정과 산출물

- 환경·도구 버전·코드 SHA·기대값/실제값·판정·다음 조치를 기록합니다. 대상 버전과 입력 자료의 종류를 구분합니다.
- 실패하면 파서/Worker/API/저장/권한/브라우저 호환 중 어디서 실패했는지 좁힙니다. 원인을 확정하지 못하면 **확인 불가**와 다음 확인 방법을 표시합니다. 기본값 추측·보호 해제·한도 제거로 통과시키지 않습니다.
- 수정 시 관련 회귀·타입·빌드·클라이언트 경계·필요한 통합 검증을 실행하고 사용자 흐름을 재검증합니다. 플랫폼 검사 없이 합성 테스트만으로 실제 Android 완료라고 하지 않습니다.
- 검증용 서버/DB는 운영과 분리한 loopback 환경을 사용합니다. 원본 APK/서명키·DB·.env·개인 경로·이메일·스크린샷의 비밀값을 Git에 올리지 않습니다.
- 기존 검토 보고서에 후속 절을 추가하고 날짜별 비식별 근거를 기록합니다. 이 문서의 합성/실제 구분을 유지하세요.
